📅 Lecture 01 | Module 01: Intro, SPA, Setup & ES6 Essentials Day 1

1. Intro to ReactJS

Meaning: A free and open-source JavaScript library for building user interfaces, especially single-page applications.
Definition: React was created by Facebook (Meta). It uses a component-based architecture and a Virtual DOM to efficiently update and render UI when data changes.
Purpose: Makes building complex, interactive, and reusable front-end interfaces faster and more maintainable than pure vanilla JS.
Example: Facebook, Instagram, Netflix, and Airbnb all use React for their front-end.
import React from 'react'; function App() { return <h1>Hello React!</h1>; } export default App;
Task: Write in your notebook 3 differences between React and plain JavaScript DOM manipulation.

2. What is SPA (Single Page Application)

Meaning: A web application that loads a single HTML page and dynamically updates content without full page reloads.
Definition: In an SPA, navigation happens on the client side using JavaScript. Only data is fetched from the server (usually as JSON), not full new HTML pages.
Purpose: Provides a smooth, app-like user experience with faster transitions and no white-screen refresh.
Example: Gmail, Facebook, Twitter/X — you click links but the page never fully reloads.
// Traditional Multi-Page: Browser requests new HTML every click // SPA: JavaScript swaps components and fetches only data
Task: List 2 advantages and 2 disadvantages of Single Page Applications.

3. Setting up ReactJS App (Vite / CRA)

Meaning: Tools that scaffold a ready-to-code React project with build configuration.
Definition: **Create React App (CRA)** was the old official tool. **Vite** is the modern, much faster alternative that uses native ES modules and instant Hot Module Replacement.
Purpose: Avoids manual Webpack/Babel configuration so developers can start coding components immediately.
Example: Running one terminal command to generate a full project folder.
# Modern way (recommended) npm create vite@latest my-app -- --template react cd my-app npm install npm run dev
Task: Create a new React project using Vite and successfully run it on localhost.

4. ES6: let & const

Meaning: Block-scoped variable declarations introduced in ES6 to replace `var`.
Definition: `let` allows reassignment but not re-declaration in the same scope. `const` creates a read-only reference (cannot be reassigned).
Purpose: Prevents accidental bugs caused by `var` hoisting and function scoping.
Example: Using `const` for values that never change and `let` for counters.
let count = 0; count = 1; // allowed const PI = 3.14; // PI = 3; // Error!
Task: Declare one `let` and one `const` variable and try reassigning both. Note the error.

5. ES6: Arrow Functions

Meaning: A shorter syntax for writing function expressions.
Definition: Arrow functions use `=>` and do not have their own `this`, `arguments`, or `super`. They inherit `this` from the surrounding scope.
Purpose: Cleaner code especially for callbacks, array methods, and React event handlers.
Example: Converting a normal function into a one-liner arrow function.
// Traditional function add(a, b) { return a + b; } // Arrow const add = (a, b) => a + b;
Task: Convert a function that multiplies two numbers into an arrow function.

6. ES6: Array Destructuring

Meaning: Unpacking values from arrays into distinct variables in a single line.
Definition: Uses square brackets `[]` on the left side of the assignment to extract array items by position.
Purpose: Makes code cleaner when working with arrays returned from functions or APIs.
Example: Extracting first and second items from an array.
const colors = ["red", "green", "blue"]; const [first, second] = colors; console.log(first); // "red"
Task: Destructure an array of 3 city names into individual variables.

7. ES6: Object Destructuring

Meaning: Unpacking properties from objects into distinct variables.
Definition: Uses curly braces `{}` on the left side to extract object properties by their key name.
Purpose: Extremely common in React for extracting props and state values cleanly.
Example: Pulling `name` and `age` out of a user object.
const user = { name: "Somesh", age: 25, role: "Trainer" }; const { name, age } = user; console.log(name); // "Somesh"
Task: Destructure `title` and `price` from a product object.

8. ES6: Spread Operator (...)

Meaning: Expands an iterable (array/object) into individual elements.
Definition: The `...` syntax copies all items from one array/object into another or into a function call.
Purpose: Used for immutable updates in React state, cloning arrays/objects, and merging data.
Example: Combining two arrays or copying an object while adding a new property.
const arr1 = [1, 2]; const arr2 = [...arr1, 3, 4]; // [1,2,3,4] const user = { name: "Alex" }; const newUser = { ...user, age: 30 }; // {name:"Alex", age:30}
Task: Use spread to clone an array of numbers and add one extra number at the end.

9. ES6: Rest Operator (...)

Meaning: Collects multiple remaining elements into a single array or object.
Definition: Looks identical to spread (`...`) but is used in function parameters or destructuring to gather “the rest” of the values.
Purpose: Handles indefinite number of arguments or remaining object properties cleanly.
Example: A function that accepts any number of scores.
function sum(...numbers) { return numbers.reduce((total, n) => total + n, 0); } sum(1, 2, 3, 4); // 10
Task: Write a function that uses rest parameters to accept any number of names and logs them.

10. ES6: Modules (import / export)

Meaning: A system to split code into multiple files and share functionality between them.
Definition: `export` makes variables/functions available outside the file. `import` brings them into another file. Can be named or default exports.
Purpose: Keeps React projects organized (one component per file) and avoids global namespace pollution.
Example: Exporting a Button component and importing it into App.jsx.
// Button.jsx export default function Button() { return <button>Click</button>; } // App.jsx import Button from './Button';
Task: Create two files. Export a function from one and import + use it in the other.

11. ES6: Optional Chaining (?.)

Meaning: A safe way to access nested object properties that might not exist.
Definition: The `?.` operator short-circuits and returns `undefined` instead of throwing an error if the reference is nullish.
Purpose: Prevents runtime crashes when dealing with API data that has missing fields.
Example: Accessing a deeply nested user address safely.
const user = { profile: { name: "Somesh" } }; console.log(user.profile?.name); // "Somesh" console.log(user.address?.city); // undefined (no error)
Task: Use optional chaining to safely read `user.settings.theme` even if settings is missing.

📅 Lecture 02 | Module 02: JSX & Components Day 2

12. What is JSX

Meaning: JavaScript XML — a syntax extension that lets you write HTML-like code inside JavaScript.
Definition: JSX is not valid JavaScript by itself. Build tools (Babel/Vite) transpile it into `React.createElement()` calls.
Purpose: Makes UI code readable and expressive while keeping the full power of JavaScript.
Example: Writing a heading directly inside a function return.
const element = <h1 className="title">Hello JSX</h1>;
Task: Write a JSX expression that renders a paragraph with your name.

13. Embedding JS in JSX & Expressions ({})

Meaning: Inserting dynamic JavaScript values inside JSX markup.
Definition: Any valid JS expression can be placed inside curly braces `{ }` within JSX. This includes variables, function calls, and ternary operators.
Purpose: Makes the UI data-driven instead of static.
Example: Showing a live counter value or a user’s name.
const name = "Somesh"; return <h1>Welcome, {name.toUpperCase()}!</h1>;
Task: Embed a calculated value (2 + 2) and a variable inside a JSX heading.

14. JSX Rules

Meaning: Strict syntax rules that JSX must follow to compile correctly.
Definition: 1) Must return a single parent element (or Fragment `<>...</>`). 2) Use `className` instead of `class`. 3) Self-close empty tags (`<img />`). 4) `camelCase` for attributes (`onClick`, `tabIndex`).
Purpose: Prevents compilation errors and keeps JSX consistent with JavaScript.
Example: Wrapping multiple elements in a Fragment.
return ( <> <h1 className="main">Title</h1> <img src="logo.png" alt="Logo" /> </> );
Task: Fix a broken JSX snippet that uses `class` and has two sibling elements without a parent.

15. Intro to Components

Meaning: The core building blocks of every React application.
Definition: A component is a reusable, independent piece of UI that returns JSX. It can be a function or a class.
Purpose: Breaks complex UIs into small, manageable, testable pieces.
Example: A `Navbar`, `Button`, `Card`, and `Footer` are all separate components.
function Welcome() { return <h1>Hello Component</h1>; }
Task: Create your first functional component called `Header` that returns an `<h1>`.

16. Types of Components

Meaning: The two historical categories of React components.
Definition: **Class Components** (old) use ES6 classes and lifecycle methods. **Functional Components** (modern standard) are plain JS functions that may use Hooks.
Purpose: Functional components + Hooks are now the recommended way; class components are mainly seen in legacy code.
Example: Same UI written both ways.
// Functional (preferred) function Hello() { return <p>Hi</p>; } // Class (legacy) class Hello extends React.Component { render() { return <p>Hi</p>; } }
Task: Write both a functional and a class component that display “React is awesome”.

17. Functional Components

Meaning: JavaScript functions that return JSX and receive props as arguments.
Definition: The modern standard way to write React UI. They become powerful when combined with Hooks (`useState`, `useEffect`, etc.).
Purpose: Simpler syntax, better performance, and easier to test than class components.
Example: A pure presentational button component.
function Button(props) { return <button>{props.label}</button>; }
Task: Create a functional component `Greeting` that accepts a `name` and displays it.

18. Reusable Components & Component Structure

Meaning: Designing components so they can be used many times with different data, and organizing files cleanly.
Definition: Reusability comes from accepting props. Good structure = one component per file, clear folder hierarchy (`components/`, `pages/`, `hooks/`).
Purpose: DRY principle (Don’t Repeat Yourself) and scalable project architecture.
Example: A single `Card` component used for products, users, and blog posts by passing different props.
// components/Card.jsx export default function Card({ title, desc }) { return ( <div className="card"> <h3>{title}</h3> <p>{desc}</p> </div> ); }
Task: Create a reusable `UserCard` component and use it three times with different names.

📅 Lecture 03 | Module 03: Props, State, Events, Lists Day 3

19. Props

Meaning: Short for “properties” — the way to pass data from a parent component to a child component.
Definition: Props are read-only. A child cannot modify the props it receives. They are passed like HTML attributes and received as a single object argument.
Purpose: Makes components dynamic and reusable with different data.
Example: Parent sends a name; child displays it.
// Parent <Welcome name="Somesh" role="Trainer" /> // Child function Welcome(props) { return <h1>Hello {props.name}, {props.role}</h1>; }
Task: Create a `Product` component that receives `title` and `price` as props and displays them.

20. State & useState Hook

Meaning: Component-level memory that can change over time and trigger re-renders.
Definition: `useState` is a Hook that returns a stateful value and a function to update it. Calling the updater function re-renders the component with the new value.
Purpose: Handles interactive data: counters, form inputs, toggles, fetched lists, etc.
Example: A simple click counter.
import { useState } from 'react'; function Counter() { const [count, setCount] = useState(0); return ( <button onClick={() => setCount(count + 1)}> Clicked {count} times </button> ); }
Task: Build a light/dark mode toggle using `useState` and a boolean.

21. Events in React

Meaning: Handling user interactions (click, change, submit, etc.) inside React components.
Definition: React uses camelCase event names (`onClick`, `onChange`) and passes a SyntheticEvent. Handler functions are passed as references (or arrow functions).
Purpose: Connects user actions to state updates and side effects.
Example: Button click increments state.
function handleClick() { alert("Button clicked!"); } return <button onClick={handleClick}>Press</button>;
Task: Create an input that logs its value to the console on every `onChange` event.

22. Conditional Rendering

Meaning: Showing or hiding UI elements based on JavaScript conditions.
Definition: Achieved with `if/else`, ternary operator (`? :`), or logical `&&` short-circuiting inside JSX.
Purpose: Displays different UI for logged-in vs guest users, loading states, error messages, etc.
Example: Show “Login” or “Logout” button depending on auth state.
{isLoggedIn ? <button>Logout</button> : <button>Login</button>} {error && <p className="error">{error}</p>}
Task: Use a boolean state to toggle between a “Show More” and “Show Less” button + text.

23. Lists & Keys

Meaning: Rendering collections of data as multiple similar components.
Definition: Use `.map()` to transform an array into an array of JSX elements. Each element must have a unique and stable `key` prop so React can track changes efficiently.
Purpose: Displays dynamic lists (todos, products, comments) and keeps reconciliation fast.
Example: Rendering a todo list.
const todos = [{id:1, text:"Learn React"}, {id:2, text:"Build App"}]; return ( <ul> {todos.map(todo => ( <li key={todo.id}>{todo.text}</li> ))} </ul> );
Task: Create an array of 5 fruits and render them as a list with proper keys.

📅 Lecture 04 | Module 04: Forms, useEffect & Styling Day 4

24. Forms (Controlled Components)

Meaning: Form inputs whose values are fully controlled by React state.
Definition: The `value` prop is set from state and the `onChange` handler updates that state. React becomes the “single source of truth”.
Purpose: Enables instant validation, character counters, conditional submit buttons, and easy data handling.
Example: A controlled name input.
const [name, setName] = useState(""); return ( <input value={name} onChange={(e) => setName(e.target.value)} /> );
Task: Build a controlled login form with email and password fields and a submit handler that console.logs the values.

25. useEffect Hook

Meaning: The Hook for performing side effects in functional components.
Definition: `useEffect(callback, dependencyArray)` runs after render. The dependency array controls when it re-runs. Return a cleanup function for subscriptions/timers.
Purpose: Data fetching, setting up listeners, timers, manually changing the DOM, logging, etc.
Example: Fetch data once when the component mounts.
import { useEffect, useState } from 'react'; useEffect(() => { document.title = `Count: ${count}`; }, [count]); // runs every time count changes
Task: Use `useEffect` to change the document title whenever a counter state updates.

26. Styling in React

Meaning: Different approaches to apply CSS to React components.
Definition: 1) Global CSS / regular stylesheets. 2) CSS Modules (`styles.module.css`). 3) Inline styles (JS object). 4) Styled-components / Tailwind / other libraries.
Purpose: Keeps styles scoped, maintainable, and consistent with component architecture.
Example: Inline style and CSS Module usage.
// Inline <div style={{ color: "red", fontSize: "20px" }}>Text</div> // CSS Module import styles from './Card.module.css'; <div className={styles.card}>Content</div>
Task: Style a card component using both an external CSS file and one inline style.

📅 Lecture 05 | Module 05: API, Router, Advanced Hooks Day 5

27. API Integration in React

Meaning: Fetching and sending data to backend servers from a React component.
Definition: Usually done with `fetch` or `axios` inside `useEffect`. Data is stored in state and rendered. Loading and error states are also managed.
Purpose: Turns static UIs into real dynamic applications powered by live data.
Example: Loading a list of users from JSONPlaceholder.
useEffect(() => { fetch("https://jsonplaceholder.typicode.com/users") .then(res => res.json()) .then(data => setUsers(data)); }, []);
Task: Fetch users from an API and display their names in a list. Show “Loading...” while waiting.

28. React Router

Meaning: The standard library for adding client-side routing/navigation to React SPAs.
Definition: Provides `BrowserRouter`, `Routes`, `Route`, `Link`, and `useNavigate` so different URLs render different components without page reload.
Purpose: Enables multi-page feel inside a single-page application (Home, About, Profile, etc.).
Example: Basic route setup.
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom'; <BrowserRouter> <Link to="/">Home</Link> <Routes> <Route path="/" element={<Home />} /> <Route path="/about" element={<About />} /> </Routes> </BrowserRouter>
Task: Install `react-router-dom` and create two pages (Home & Contact) with working navigation links.

29. useRef Hook

Meaning: A Hook that returns a mutable ref object which persists across renders without causing re-renders.
Definition: Commonly used to directly access DOM elements (`inputRef.current.focus()`) or to store any mutable value that doesn’t need to trigger UI updates.
Purpose: Managing focus, media players, previous values, or integrating with non-React libraries.
Example: Auto-focusing an input on mount.
const inputRef = useRef(null); useEffect(() => { inputRef.current.focus(); }, []); return <input ref={inputRef} />;
Task: Create a button that, when clicked, focuses a text input using `useRef`.

30. useMemo & useCallback Hooks

Meaning: Performance optimization Hooks that memoize expensive values or functions.
Definition: `useMemo` caches the result of a calculation. `useCallback` caches the function definition itself so it keeps the same reference between renders.
Purpose: Prevents unnecessary re-renders of child components and avoids re-calculating heavy operations.
Example: Memoizing a filtered list.
const filtered = useMemo(() => { return items.filter(i => i.active); }, [items]); const handleClick = useCallback(() => { console.log("clicked"); }, []);
Task: Use `useMemo` to filter a large array only when the source array changes.

31. Custom Hooks

Meaning: Reusable functions that start with `use` and can call other Hooks inside them.
Definition: Custom Hooks extract component logic into shareable functions (e.g., `useLocalStorage`, `useFetch`, `useToggle`).
Purpose: Shares stateful logic between multiple components without repeating code or using higher-order components.
Example: A simple toggle hook.
function useToggle(initial = false) { const [value, setValue] = useState(initial); const toggle = () => setValue(v => !v); return [value, toggle]; } // usage const [isOpen, toggleOpen] = useToggle();
Task: Create a custom hook `useDocumentTitle` that sets the page title.
