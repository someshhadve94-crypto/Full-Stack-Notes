1. Intro to MySQL

Meaning: An open-source Relational Database Management System (RDBMS) that stores data in structured tables using rows and columns.
Definition: MySQL uses Structured Query Language (SQL) to perform database operations. It supports ACID properties, foreign key relationships, and high-concurrency read/write operations.
Purpose: Serves as persistent, structured backend data storage for web applications like e-commerce, banking, and social networks.
Example: Storing registered users, product inventories, and customer orders inside dedicated tables.
SHOW DATABASES; USE my_store_db;
Task: Explain in your notebook why relational databases use structured tables rather than unstructured plain text files.

2. Install XAMPP & Usage of XAMPP

Meaning: Setting up a local web server environment that bundles Apache, MariaDB/MySQL, PHP, and phpMyAdmin.
Definition: XAMPP is a free cross-platform software stack. Starting the Apache and MySQL modules in the XAMPP Control Panel activates local database access at `localhost` (port 3306).
Purpose: Provides a simple local GUI (phpMyAdmin) and local database server for development without requiring cloud hosting.
Example: Accessing `http://localhost/phpmyadmin` to visually inspect database tables.
# Start Apache & MySQL from XAMPP Control Panel # Open browser: http://localhost/phpmyadmin
Task: Launch XAMPP, start Apache and MySQL, and log into phpMyAdmin in your web browser.

3. Connecting Python & MySQL using PIP

Meaning: Installing the database driver module to allow Python scripts to communicate with a MySQL database server.
Definition: Installed using `pip install mysql-connector-python`. Inside Python, `mysql.connector.connect()` establishes a socket connection using host, user, password, and database parameters.
Purpose: Enables automated backend database queries directly from Python code.
Example: Connecting Python to local XAMPP MySQL database.
pip install mysql-connector-python # python_script.py import mysql.connector db = mysql.connector.connect( host="localhost", user="root", password="" ) cursor = db.cursor() cursor.execute("SHOW DATABASES")

4. Creating Database & Creating Tables

Meaning: SQL commands to initialize a new database container and define relational data tables inside it.
Definition: `CREATE DATABASE db_name;` creates the container. `CREATE TABLE table_name (col1 type, col2 type);` defines table schemas, column names, and data types (VARCHAR, INT, FLOAT, DATE).
Purpose: Sets up structured storage schemas for domain entities like Users, Accounts, or Products.
Example: Creating a `students` table with ID, Name, and Age columns.
CREATE DATABASE hospital_db; USE hospital_db; CREATE TABLE patients ( patient_id INT, full_name VARCHAR(100), age INT, disease VARCHAR(100) );

5. MySQL Constraints (PRIMARY KEY, UNIQUE, NOT NULL, FOREIGN KEY, DEFAULT)

Meaning: Rules enforced on data columns to ensure accuracy, integrity, and uniqueness.
Definition: **PRIMARY KEY** uniquely identifies every record. **AUTO_INCREMENT** auto-generates IDs. **UNIQUE** prevents duplicates. **NOT NULL** forbids empty values. **DEFAULT** sets fallback values. **FOREIGN KEY** links child tables to parent tables.
Purpose: Guarantees database data integrity and prevents invalid or orphaned data entries.
Example: Setting `account_no` as a unique primary key that auto-increments.
CREATE TABLE accounts ( acc_no INT PRIMARY KEY AUTO_INCREMENT, holder_name VARCHAR(100) NOT NULL, email VARCHAR(100) UNIQUE, balance FLOAT DEFAULT 0.00 );

6. CRUD: INSERT & SELECT

Meaning: Standard operations to add new data rows and retrieve existing data rows from tables.
Definition: `INSERT INTO table (cols) VALUES (vals);` adds new records. `SELECT cols FROM table;` queries and retrieves records. `SELECT *` retrieves all columns.
Purpose: Core fundamental operations for saving form submissions and reading data back to display on the UI.
Example: Inserting a new patient into a hospital database and querying all patients.
INSERT INTO patients (full_name, age, disease) VALUES ('Aarav Sharma', 32, 'Fever'); SELECT patient_id, full_name FROM patients;

7. SQL Injection & Parameterized Queries

Meaning: A major security vulnerability where attackers inject malicious SQL statements through user input fields.
Definition: Dynamic string concatenation (`"SELECT * FROM users WHERE user='" + input + "'"` ) lets attackers bypass login with `' OR '1'='1`. **Parameterized Queries** (using `%s` placeholders with tuples) separate code from data safely.
Purpose: Protects databases against unauthorized access, data destruction, and credential leaks.
Example: Safe query execution using Python MySQL Connector parameter placeholders.
# UNSAFE (Vulnerable to SQL Injection): # query = f"SELECT * FROM users WHERE name='{user_input}'" # SAFE (Parameterized Query): query = "SELECT * FROM users WHERE name = %s AND status = %s" values = (user_input, "active") cursor.execute(query, values)
Task: Write a Python program that safely inserts user inputs into MySQL using `%s` placeholders.

📅 Lecture 03 | Module 03: Filtering & Sorting Day 3

8. Filtering: WHERE, AND, OR, LIKE

Meaning: Restricting SQL query results based on specific conditions and pattern matching.
Definition: `WHERE` specifies condition rules. `AND` requires all conditions true; `OR` requires at least one condition true. `LIKE` handles wildcard search (`%` for any string, `_` for single character).
Purpose: Powers search bars, price filters, category filters, and user searches.
Example: Finding all products in 'Clothing' with price under 500, or names starting with 'Shirt'.
SELECT * FROM products WHERE category = 'Clothing' AND price < 500; SELECT * FROM products WHERE product_name LIKE 'Shirt%';
Task: Query all products whose name contains the letter 'a' using `LIKE '%a%'`.

9. Sorting & Limiting: ORDER BY & LIMIT

Meaning: Sorting database result sets in specific order and capping total returned row counts.
Definition: `ORDER BY column ASC | DESC` sorts output numerically or alphabetically. `LIMIT n` restricts returned rows to `n` items.
Purpose: Powers pagination, "Top 10" leaderboards, and "Sort by Price High to Low" features.
Example: Fetching the top 5 most expensive products.
SELECT * FROM products ORDER BY price DESC LIMIT 5;

📅 Lecture 04 | Module 04: CRUD - Update & Delete Day 4

10. CRUD: UPDATE & DELETE

Meaning: Modifying existing database records and removing obsolete records from tables.
Definition: `UPDATE table SET col = val WHERE condition;` alters existing rows. `DELETE FROM table WHERE condition;` removes matching rows. **CRITICAL:** Always include a `WHERE` clause, otherwise ALL rows in the table will be updated or deleted!
Purpose: Allows users to update profile details, change account balances, or cancel orders.
Example: Updating a customer balance after a deposit, or deleting a cancelled patient appointment.
UPDATE accounts SET balance = balance + 500.00 WHERE acc_no = 101; DELETE FROM patients WHERE patient_id = 5;

📅 Lecture 05 | Module 05: Aggregate Functions & Grouping Day 5

11. Aggregate Functions (COUNT, SUM, AVG, MIN, MAX)

Meaning: SQL functions that perform calculations on multiple rows of a column and return a single summary value.
Definition: `COUNT()` returns row count. `SUM()` totals values. `AVG()` calculates average. `MIN()` / `MAX()` find lowest/highest values.
Purpose: Powers dashboard statistics, total sales metrics, and business reports.
Example: Calculating total revenue and total customer count.
SELECT COUNT(*) AS total_patients FROM patients; SELECT SUM(balance) AS total_deposits FROM accounts; SELECT AVG(price) AS avg_price, MAX(price) AS highest FROM products;
Task: Write a query to count total products and calculate the average product price in your database.

12. Grouping Data: GROUP BY & HAVING

Meaning: Categorizing identical data rows into summary groups and filtering aggregated results.
Definition: `GROUP BY column` groups identical column values together for aggregation. `HAVING condition` filters the *grouped summary results* (unlike `WHERE` which filters individual raw rows before grouping).
Purpose: Generates category breakdown analytics (e.g., total sales per category, patient count per disease).
Example: Showing total stock per category where total stock exceeds 10 items.
SELECT category, COUNT(*) AS item_count, SUM(stock) AS total_stock FROM products GROUP BY category HAVING total_stock > 10;

📅 Lecture 06 | Module 06: Joins & Relationships Day 6

13. Table Relationships & Foreign Keys

Meaning: Connecting related data tables together through shared Key columns.
Definition: Relationships include **One-to-Many** (1 Customer -> Many Orders), **Many-to-Many** (Many Students -> Many Courses via junction table), and **One-to-One**. A `FOREIGN KEY` in the child table references the `PRIMARY KEY` of the parent table.
Purpose: Eliminates data redundancy and establishes relational integrity across complex system tables.
Example: Linking an `orders` table to a `customers` table via `customer_id`.
CREATE TABLE orders ( order_id INT PRIMARY KEY AUTO_INCREMENT, order_date DATE, customer_id INT, FOREIGN KEY (customer_id) REFERENCES customers(acc_no) );
Task: Draw an ER diagram in your notebook showing a One-to-Many relationship between Customers and Transactions.

14. SQL Joins (INNER JOIN, LEFT JOIN, RIGHT JOIN)

Meaning: Combining columns from two or more tables based on a related common column.
Definition: **INNER JOIN** returns records matching in both tables. **LEFT JOIN** returns all records from left table + matching records from right. **RIGHT JOIN** returns all records from right table + matching records from left.
Purpose: Pulls unified complete datasets across relational schemas for receipts, profiles, and order histories.
Example: Fetching order details along with customer name and email.
SELECT orders.order_id, customers.holder_name, orders.order_date FROM orders INNER JOIN customers ON orders.customer_id = customers.acc_no; SELECT customers.holder_name, orders.order_id FROM customers LEFT JOIN orders ON customers.acc_no = orders.customer_id;
