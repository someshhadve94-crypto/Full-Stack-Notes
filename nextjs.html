1. Intro to Next.js

Meaning: A production-ready React framework for building full-stack web applications.
Definition: Developed by Vercel, Next.js extends React by providing hybrid rendering strategies (SSR, SSG, ISR, CSR), file-system routing, automatic code splitting, and server-side optimizations out of the box.
Purpose: Solves single-page application SEO limitations and slow initial page loads found in plain client-side React.
Example: Building high-performance, search-engine-indexed e-commerce and news platforms.
// React Library + Server-Side Rendering + File Routing = Next.js Framework

2. SSR (Server-Side Rendering) vs CSR (Client-Side Rendering)

Meaning: Comparison between generating HTML on the backend server versus rendering it inside the browser.
Definition: **CSR** (Vanilla React) sends an empty HTML shell; JavaScript builds the UI in the browser. **SSR** (Next.js) renders full HTML on the server per request, sending ready HTML to the browser instantly for superior SEO.
Purpose: Drastically reduces First Contentful Paint (FCP) time and ensures search engine web crawlers index content properly.
Example: Viewing page source: CSR shows empty `
`; SSR shows complete populated HTML text.
# CSR Flow: Server sends JS bundle ---> Browser executes JS ---> UI appears (Slow SEO) # SSR Flow: Server renders HTML ---> Sends populated HTML ---> UI appears instantly (Great SEO)
Task: Inspect the raw page source of a plain React site versus a Next.js site in Chrome DevTools.

3. App Router vs Pages Router Architecture

Meaning: The two architectural routing models provided by Next.js.
Definition: **Pages Router** (Legacy) uses the `pages/` directory where every file is a route. **App Router** (Modern Next.js 13+) uses the `app/` directory built on React Server Components, supporting nested layouts, streaming, and `page.jsx` conventions.
Purpose: App Router provides finer control over layout inheritance, performance, and server component execution.
Example: Route `/about` in App Router = `app/about/page.jsx`.
// App Router Structure: // app/ // ├── layout.jsx (Root Layout) // ├── page.jsx (Home Page /) // └── about/ // └── page.jsx (About Page /about)

4. Setting Up Next.js (`create-next-app`)

Meaning: Initializing a new Next.js project using the official CLI initialization tool.
Definition: Executed via `npx create-next-app@latest`. Prompts choices for TypeScript, Tailwind CSS, App Router, ESLint, and import aliases (`@/*`).
Purpose: Scaffolds a zero-configuration, production-configured Next.js workspace instantly.
Example: Initializing and running a Next.js App Router project locally.
npx create-next-app@latest my-next-app cd my-next-app npm run dev # App starts on http://localhost:3000

📅 Lecture 02 | Module 02: Routing, Layouts & Dynamic Routes Day 2

5. File-Based Routing System

Meaning: Defining application URL routes through file and folder conventions rather than manual JavaScript routing tables.
Definition: Folders define route segments. A `page.jsx` file inside a folder makes that segment publicly accessible. Special files: `layout.jsx`, `loading.jsx`, `error.jsx`, `not-found.jsx`.
Purpose: Automates routing setup and maintains clean file organization without third-party routing packages.
Example: `app/services/page.jsx` automatically creates the route `/services`.
// app/services/page.jsx export default function ServicesPage() { return <h1>Our Services</h1>; }

6. Navigation: `` & `useRouter`

Meaning: Performing client-side transitions between Next.js pages without full page refreshes.
Definition: `` prefetches page routes in the background. The `useRouter()` hook (`next/navigation`) enables programmatic navigation (e.g., `router.push('/dashboard')`).
Purpose: Delivers lightning-fast, app-like client navigation transitions.
Example: Navigating using `` and programmatic button triggers.
import Link from 'next/link'; import { useRouter } from 'next/navigation'; export default function Navigation() { const router = useRouter(); return ( <nav> <Link href="/about">About Us</Link> <button onClick={() => router.push('/login')}>Login</button> </nav> ); }

7. Dynamic Routes (`[id]`)

Meaning: Creating routes that match dynamic URL parameter segments like product IDs or blog slugs.
Definition: Folder names wrapped in square brackets `[id]` capture dynamic URL values, accessible inside the page via the `params` prop object (`params.id`).
Purpose: Renders dynamic detail pages for products, users, or articles using a single component template.
Example: URL `/products/101` matches folder `app/products/[id]/page.jsx`.
// app/products/[id]/page.jsx export default function ProductDetail({ params }) { return <h1>Displaying Product ID: {params.id}</h1>; }

8. Layouts, Templates & Special UI Files

Meaning: Shared UI wrappers that preserve state across route navigations, plus automatic loading/error fallbacks.
Definition: `layout.jsx` wraps nested child pages without re-rendering the shared layout on route changes. `loading.jsx` displays instant React Suspense fallbacks. `error.jsx` catches runtime exceptions.
Purpose: Maintains shared navbars/footers and improves user experience during slow page loads.
Example: Root layout wrapping all pages with a navigation header.
// app/layout.jsx export default function RootLayout({ children }) { return ( <html lang="en"> <body> <header>My Navbar</header> <main>{children}</main> </body> </html> ); }

📅 Lecture 03 | Module 03: Server vs Client Components & Data Fetching Day 3

9. Server Components vs Client Components (`'use client'`)

Meaning: The fundamental paradigm split in Next.js App Router between server-executed and browser-executed components.
Definition: By default, **ALL** App Router components are **React Server Components (RSC)** (zero JS bundle sent to client). To use hooks (`useState`, `useEffect`, `useRouter`) or browser event listeners (`onClick`), add the `'use client'` directive at the top of the file.
Purpose: Keeps client bundle size small while isolating client interactivity where strictly needed.
Example: Adding `'use client'` to an interactive counter button.
'use client'; // Required for hooks and event listeners! import { useState } from 'react'; export default function Counter() { const [count, setCount] = useState(0); return <button onClick={() => setCount(count + 1)}>{count}</button>; }
Task: Write a component using `useState` and verify that forgetting `'use client'` throws a build error.

10. Server-Side Data Fetching & Caching

Meaning: Fetching backend data directly inside async Server Components without `useEffect` or client API calls.
Definition: Next.js extends the native `fetch()` Web API to support automatic request deduplication, caching, and revalidation (`{ next: { revalidate: 60 } }`).
Purpose: Eliminates loading spinners on the client by delivering pre-rendered, data-populated HTML directly from the server.
Example: Fetching data asynchronously inside an App Router Server Component.
// Server Component (Async/Await directly!) export default async function UsersPage() { const res = await fetch('https://jsonplaceholder.typicode.com/users', { next: { revalidate: 3600 } // Revalidate every hour }); const users = await res.json(); return ( <ul> {users.map(u => <li key={u.id}>{u.name}</li>)} </ul> ); }
Task: Fetch an array of posts asynchronously inside a Server Component and render them in a list.

11. Next.js Server Actions

Meaning: Executing asynchronous server-side code directly from HTML forms without creating separate REST API endpoints.
Definition: Defined using the `'use server'` directive. Can be called inside HTML `
` elements to perform database writes directly on the server.
Purpose: Simplifies form submissions, database mutations, and revalidation without writing custom API routes.
Example: Handling form submission directly on the server using Server Actions.
import { revalidatePath } from 'next/cache'; export default function AddItemForm() { async function createItem(formData) { 'use server'; const itemName = formData.get('itemName'); // Save to Database directly... revalidatePath('/items'); } return ( <form action={createItem}> <input name="itemName" required /> <button type="submit">Add Item</button> </form> ); }
Task: Build a simple form with a Server Action that logs the form input on the server terminal upon submission.

📅 Lecture 04 | Module 04: Image & Font Optimization, SEO & Route Handlers Day 4

12. Image & Font Optimization (`next/image` & `next/font`)

Meaning: Built-in Next.js components that optimize media and typography automatically.
Definition: `` auto-resizes, converts images to modern WebP/AVIF formats, and prevents Layout Shift (CLS). `next/font` hosts Google Fonts locally at build time with zero external network requests.
Purpose: Dramatically improves Core Web Vitals, Google Lighthouse scores, and page load speed.
Example: Using Next.js Image component and Google Fonts.
import Image from 'next/image'; import { Inter } from 'next/font/google'; const inter = Inter({ subsets: ['latin'] }); export default function Profile() { return ( <div class={inter.className}> <Image src="/avatar.jpg" alt="Profile" width={100} height={100} priority /> </div> ); }

13. Metadata & SEO Optimization

Meaning: Managing document head metadata (`title`, `description`, OpenGraph cards) for Search Engine Optimization.
Definition: Exporting a `metadata` object or `generateMetadata()` function from `layout.jsx` or `page.jsx` files.
Purpose: Ensures search engine web crawlers and social media platforms display accurate preview cards for every page route.
Example: Static and dynamic metadata exports.

14. API Routes & Route Handlers (`route.js`)

Meaning: Creating backend RESTful API endpoints inside the Next.js App Router workspace.
Definition: Created using `route.js` files. Named exported functions handle specific HTTP methods: `GET`, `POST`, `PUT`, `DELETE`, `PATCH`. Returns `NextResponse.json()`.
Purpose: Allows building complete full-stack web applications with backend API endpoints in one unified project.
Example: Creating a `route.js` file for `/api/users`.
// app/api/users/route.js import { NextResponse } from 'next/server'; export async function GET(request) { const users = [{ id: 1, name: 'Somesh Hadve' }]; return NextResponse.json(users); } export async function POST(request) { const body = await request.json(); return NextResponse.json({ message: 'User created', data: body }, { status: 201 }); }
