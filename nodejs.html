📅 Lecture 01 | Module 01: Intro to NodeJS & Module System Day 1

1. Intro to NodeJS

Meaning: A cross-platform, open-source JavaScript runtime environment that executes JS code outside the web browser.
Definition: Built on Google Chrome's V8 JavaScript engine. NodeJS operates on a single-threaded, non-blocking, event-driven I/O architecture.
Purpose: Enables developers to write backend server-side code, REST APIs, and command-line tools using JavaScript.
Example: Running `node app.js` in terminal to execute backend JavaScript.
// Verify Node installation in terminal: node -v npm -v
Task: Open your terminal, check `node -v`, and execute a simple `console.log("Hello Node")` script.

2. NodeJS Modules System

Meaning: Reusable blocks of code encapsulated into separate files to organize backend applications.
Definition: Node supports 3 module types: **Core Built-in Modules** (`fs`, `http`, `path`), **Local Custom Modules** (written by developer), and **Third-Party Modules** (installed via NPM).
Purpose: Promotes code modularity, maintainability, and prevents namespace pollution.
Example: Importing built-in modules vs custom user helper files.
// Core Module const fs = require('fs'); // Local Module const math = require('./mathUtils');
Task: List 3 core modules and 3 third-party NPM modules in your notebook.

3. Module Exports & Require (`require` & `module.exports`)

Meaning: The CommonJS module syntax used in NodeJS to export and import functions/objects between files.
Definition: `module.exports` exposes functions, objects, or values from a file. `require('./filepath')` imports that exposed functionality into another file.
Purpose: Connects separate application files together into a cohesive backend system.
Example: Exporting math utility functions and requiring them in `app.js`.
// mathUtils.js const add = (a, b) => a + b; const multiply = (a, b) => a * b; module.exports = { add, multiply }; // app.js const { add, multiply } = require('./mathUtils'); console.log(add(5, 10)); // 15
Task: Create a custom module `calculator.js` that exports `add`, `subtract`, and `divide` functions, then import and test them in `index.js`.

📅 Lecture 02 | Module 02: Core Built-In Modules (FS, HTTP, Path, OS, Events) Day 2

4. FS (File System) Module

Meaning: Built-in module providing APIs to read, write, update, delete, and manage files on the server disk.
Definition: Offers both synchronous (`readFileSync`) and asynchronous non-blocking (`readFile`, promises) file operations.
Purpose: Used for logging server events, reading configuration files, or managing file uploads.
Example: Writing text to a file asynchronously and reading it back.
const fs = require('fs'); // Write File fs.writeFile('log.txt', 'Server started successfully!', (err) => { if (err) throw err; console.log('File written.'); }); // Read File fs.readFile('log.txt', 'utf8', (err, data) => { if (err) throw err; console.log(data); });
Task: Write a Node script that creates a file `notes.txt`, appends text to it using `fs.appendFile`, and logs the contents.

5. HTTP Module

Meaning: Core module allowing NodeJS to transfer data over HTTP and create web servers.
Definition: `http.createServer((req, res) => {})` listens on a specified port (e.g., 3000), accepts incoming client requests (`req`), and returns HTTP responses (`res`).
Purpose: Enables building raw HTTP web servers and RESTful API endpoints without third-party frameworks.
Example: Starting a web server returning JSON data.
const http = require('http'); const server = http.createServer((req, res) => { res.writeHead(200, { 'Content-Type': 'application/json' }); res.end(JSON.stringify({ message: "Hello from NodeJS Server!" })); }); server.listen(3000, () => { console.log('Server running on http://localhost:3000'); });
Task: Create an HTTP server that returns HTML `<h1>Welcome to Somesh Hadve's Server</h1>` on port 5000.

6. Path Module

Meaning: Core module providing utilities for working with file and directory paths.
Definition: Handles path resolution cross-platform (Windows `\` vs Linux `/`). Key methods: `path.join()`, `path.resolve()`, `path.extname()`, `path.basename()`.
Purpose: Prevents file path errors when deploying code across different operating systems.
Example: Safely joining directory paths and getting file extensions.
const path = require('path'); const filePath = path.join(__dirname, 'uploads', 'image.png'); console.log(filePath); console.log(path.extname(filePath)); // '.png'
Task: Use `path.extname()` and `path.basename()` on a sample file path and log the outputs.

7. OS Module

Meaning: Built-in module providing operating system information and system metrics.
Definition: Offers functions to inspect CPU architecture (`os.arch()`), memory usage (`os.totalmem()`, `os.freemem()`), CPU details (`os.cpus()`), and uptime (`os.uptime()`).
Purpose: Used for server health monitoring, load balancing, and diagnostic logging.
Example: Printing total free memory available on the server.
const os = require('os'); console.log('OS Architecture:', os.arch()); console.log('Free Memory (MB):', os.freemem() / (1024 * 1024)); console.log('CPU Cores:', os.cpus().length);
Task: Write a script that checks server free memory percentage and warns if free memory drops below 20%.

8. Events Module (`EventEmitter`)

Meaning: Core module enabling event-driven architecture through custom event triggers and listeners.
Definition: Uses the `EventEmitter` class. Events are registered with `.on('eventName', callback)` and triggered with `.emit('eventName', data)`.
Purpose: Powers NodeJS asynchronous event handling, web sockets, logging, and chat systems.
Example: Triggering a user registration event listener.
const EventEmitter = require('events'); const customEmitter = new EventEmitter(); // Listener customEmitter.on('userSignedUp', (user) => { console.log(`Sending welcome email to ${user.email}`); }); // Trigger Event customEmitter.emit('userSignedUp', { email: 'somesh@example.com' });
Task: Create an EventEmitter that listens for an 'orderPlaced' event and logs order details.

📅 Lecture 03 | Module 03: Streams, URL & Querystring Modules Day 3

9. Streams Module (Readable, Writable, Transform & Pipe)

Meaning: Handling data processing sequentially in small chunks without loading full files into memory at once.
Definition: 4 Stream types: **Readable** (`fs.createReadStream`), **Writable** (`fs.createWriteStream`), **Duplex**, and **Transform**. `.pipe()` pipes readable stream data directly into a writable stream.
Purpose: Extremely memory efficient when handling massive video files, logs, or large dataset transfers.
Example: Copying a large 1GB file chunk by chunk using `.pipe()`.
const fs = require('fs'); const readStream = fs.createReadStream('largeVideo.mp4'); const writeStream = fs.createWriteStream('copyVideo.mp4'); // Memory-efficient piping readStream.pipe(writeStream);
Task: Pipe a large file read stream into an HTTP response stream using `readStream.pipe(res)`.

10. URL Module

Meaning: Built-in module for parsing, resolving, and formatting URL address strings.
Definition: Provides the modern `URL` Web API class to extract protocol, hostname, pathname, port, and query parameters (`searchParams`).
Purpose: Parses incoming client request URLs to handle API routing and query string parameters.
Example: Parsing query parameters from a request URL.
const myUrl = new URL('https://example.com:8080/products?category=shoes&page=2'); console.log(myUrl.hostname); // 'example.com' console.log(myUrl.pathname); // '/products' console.log(myUrl.searchParams.get('category')); // 'shoes'
Task: Create a script that parses a URL string and logs `host`, `pathname`, and query value `id`.

11. Querystring Module

Meaning: Legacy built-in module specifically for parsing and formatting URL query strings.
Definition: `querystring.parse('a=1&b=2')` converts query strings into JavaScript objects. `querystring.stringify(obj)` converts objects into query strings.
Purpose: Handles raw form submission URL-encoded data (`application/x-www-form-urlencoded`).
Example: Converting form POST query data into a readable JS object.
const querystring = require('querystring'); const parsed = querystring.parse('name=Somesh&role=Trainer'); console.log(parsed.name); // 'Somesh' const stringified = querystring.stringify({ status: 'active', page: 1 }); console.log(stringified); // 'status=active&page=1'
Task: Parse the query string `search=laptop&minPrice=500` and output the resulting object keys.

📅 Lecture 04 | Module 04: Asynchronous Node & Project Day 4

12. Asynchronous Architecture & Event Loop

Meaning: How NodeJS handles thousands of concurrent requests on a single thread without blocking execution.
Definition: Heavy I/O tasks are delegated to the underlying operating system or `libuv` thread pool. Upon completion, callbacks enter the Event Loop queue (`Microtask Queue` & `Task Queue`) to be executed.
Purpose: Delivers high scalability, throughput, and low latency for network-heavy web applications.
Example: Non-blocking file reading using `fs.promises`.
const fs = require('fs').promises; async function readFileAsync() { try { const data = await fs.readFile('data.json', 'utf8'); console.log(JSON.parse(data)); } catch (err) { console.error('Error:', err); } } readFileAsync();
Task: Convert a callback-based `fs.readFile` script into an `async/await` promise function using `fs.promises`.
