📅 Lecture 01 | Module 01: Scope, Closures & Functional Patterns Day 1

1. Lexical Scope & Scope Chain

Meaning: How variable accessibility is determined strictly by the physical position of functions inside the source code at compile time.
Definition: Inner functions have access to variables declared in their outer enclosing scope. When a variable is referenced, JS searches locally; if not found, it traverses up the **Scope Chain** to the global environment.
Purpose: Establishes predictable variable lookup rules and encapsulation boundaries across nested functions.
Example: An inner function accessing a global variable through the scope chain.
const globalVar = "Global"; function outer() { const outerVar = "Outer"; function inner() { console.log(globalVar, outerVar); // Accesses both via Scope Chain } inner(); } outer();
Task: Draw a scope chain diagram for a 3-level nested function hierarchy in your notebook.

2. Closures & Private Variables

Meaning: A function bundled together with references to its surrounding lexical environment, allowing it to remember outer variables even after the outer function has finished executing.
Definition: Created whenever an inner function is returned or passed out of an outer function. The inner function retains access to the outer function's scope variables, effectively creating private encapsulation.
Purpose: Enables data privacy, state preservation, function factories, and module design patterns.
Example: A counter with a private internal state variable.
function createCounter() { let count = 0; // Private variable! return { increment: () => ++count, decrement: () => --count, getCount: () => count }; } const counter = createCounter(); console.log(counter.increment()); // 1 console.log(counter.count); // undefined (Safe & Encapsulated!)
Task: Create a function `createBankAccount(initialBalance)` that encapsulates `balance` using a closure.

3. IIFE (Immediately Invoked Function Expressions)

Meaning: A JavaScript function that runs as soon as it is defined.
Definition: Wrapped inside grouping parentheses `(function() { ... })()` to prevent the function declaration from polluting the global scope. Executes immediately upon parsing.
Purpose: Creates isolated scope blocks to initialize setup code without polluting global namespace or colliding with other scripts.
Example: Isolating initialization logic using an IIFE.
(function() { const tempConfig = "API_KEY_12345"; console.log("IIFE Initialized with:", tempConfig); })(); // tempConfig is inaccessible outside (No global pollution)
Task: Write an IIFE that calculates and logs the execution start time without leaving global variables behind.

4. Function Currying

Meaning: An advanced functional programming technique that transforms a function with multiple arguments into a sequence of nesting functions taking one argument each.
Definition: Instead of `f(a, b, c)`, currying turns a function into `f(a)(b)(c)`. Utilizes closures to remember passed parameters across step-by-step function calls.
Purpose: Promotes function reusability, partial application, and configurable utility functions.
Example: Currying a discount calculation function.
// Standard: multiply(a, b) // Curried Version: const multiply = a => b => a * b; const double = multiply(2); // Partial application console.log(double(5)); // 10 console.log(multiply(3)(4)); // 12
Task: Write a curried function `volume(length)(width)(height)` and test it.

📅 Lecture 02 | Module 02: Event Loop, Execution Context & Async Deep Dive Day 2

5. Call Stack, Execution Context & Hoisting

Meaning: How the JS engine parses, manages, and executes code in memory.
Definition: **Execution Context** has 2 phases: Creation Phase (Memory Allocation/Hoisting) and Execution Phase. **Call Stack** is a LIFO (Last In, First Out) stack tracking function execution frames.
Purpose: Explains how variables/functions are hoisted and how synchronous call stacks behave under execution.
Example: Function calls pushing and popping frames off the Call Stack.
function first() { second(); } function second() { console.log("Done"); } first(); // Pushes first() -> Pushes second() -> Pops second() -> Pops first()
Task: Explain in your notebook why `var` declarations are hoisted as `undefined` while `let`/`const` enter the Temporal Dead Zone (TDZ).

6. The Event Loop, Microtask & Macrotask Queues

Meaning: The concurrency model mechanism that manages asynchronous callback execution in single-threaded JavaScript.
Definition: The **Event Loop** continuously checks if the Call Stack is empty. If empty, it empties the **Microtask Queue** (Promises, `queueMicrotask`, `process.nextTick`) FIRST before picking one task from the **Macrotask Queue** (`setTimeout`, `setInterval`, I/O).
Purpose: Crucial for predicting asynchronous code execution order and avoiding UI thread blocking.
Example: Order of execution between Promise microtasks and setTimeout macrotasks.
console.log("1. Start"); setTimeout(() => console.log("2. Macrotask Timeout"), 0); Promise.resolve().then(() => console.log("3. Microtask Promise")); console.log("4. End"); // Output Order: 1. Start -> 4. End -> 3. Microtask Promise -> 2. Macrotask Timeout
Task: Trace and write down the exact console output sequence for a script containing `setTimeout`, `Promise`, and `console.log`.

7. Promise Combinators (`Promise.all`, `allSettled`, `race`, `any`)

Meaning: Static utility methods for handling multiple asynchronous promises concurrently.
Definition: `Promise.all`: Resolves when ALL pass; rejects on FIRST failure. `Promise.allSettled`: Resolves when ALL complete (returns array of status objects). `Promise.race`: Resolves/rejects as soon as the FIRST promise settles. `Promise.any`: Resolves as soon as the FIRST promise succeeds.
Purpose: Manages parallel network requests efficiently in high-performance applications.
Example: Fetching multiple API endpoints in parallel using `Promise.all`.
const p1 = fetch('/api/users'); const p2 = fetch('/api/posts'); Promise.all([p1, p2]) .then(([usersRes, postsRes]) => console.log("Both APIs fetched!")) .catch(err => console.error("One failed:", err));
Task: Write a script comparing `Promise.all` vs `Promise.allSettled` when one promise rejects.

📅 Lecture 03 | Module 03: Prototypes, OOP & Class Mechanics Day 3

8. Prototype & Prototype Chain (`__proto__` vs `prototype`)

Meaning: JavaScript's underlying object-oriented inheritance mechanism based on prototype linkage.
Definition: Every object has an internal link (`__proto__`) to its prototype object. Constructor functions have a `.prototype` property. When a property is queried, JS traverses up the **Prototype Chain** until it finds the property or hits `null`.
Purpose: Allows memory-efficient method sharing across thousands of object instances.
Example: Adding a shared method to a constructor function's prototype.
function Person(name) { this.name = name; } // Shared prototype method (Memory Efficient) Person.prototype.sayHi = function() { console.log(`Hi, I am ${this.name}`); }; const user1 = new Person("Somesh"); user1.sayHi();
Task: Inspect `user1.__proto__` in Chrome console and verify `user1.__proto__ === Person.prototype`.

9. ES6 Classes & Prototypal Inheritance (`extends`, `super`)

Meaning: Syntactic sugar over JavaScript's prototypal inheritance model providing clean object-oriented class syntax.
Definition: Uses `class`, `constructor()`, `extends` (subclassing), and `super()` (calling parent constructor). Supports static methods (`static`) and private fields (`#privateField`).
Purpose: Simplifies object-oriented programming patterns and inheritance structures in JavaScript.
Example: Inheriting methods from a parent class using `extends` and `super`.
class Vehicle { constructor(brand) { this.brand = brand; } start() { console.log(`${this.brand} starting...`); } } class Car extends Vehicle { constructor(brand, model) { super(brand); // Call parent constructor this.model = model; } } const myCar = new Car("Toyota", "Camry"); myCar.start();

10. Object Immutability & Descriptors (`freeze`, `seal`, `defineProperty`)

Meaning: Controlling object property behaviors, writability, configurability, and immutability.
Definition: `Object.defineProperty()` sets property descriptors (`writable`, `enumerable`, `configurable`). `Object.seal()` prevents adding/deleting properties. `Object.freeze()` makes an object completely immutable (shallow freeze).
Purpose: Secures application state configurations and constants against accidental modification.
Example: Freezing an application configuration object.
const CONFIG = Object.freeze({ API_URL: "https://api.example.com", VERSION: "1.0.0" }); // CONFIG.VERSION = "2.0.0"; // Fails silently or throws error in strict mode!

📅 Lecture 04 | Module 04: The `this` Keyword & Method Borrowing Day 4

11. Mechanics of the `this` Keyword

Meaning: A dynamic execution context reference determined strictly by **how** a function is called.
Definition: 1) Global scope: `window` (or `undefined` in strict mode). 2) Object Method: refers to the calling object. 3) Constructor (`new`): refers to the newly created object. 4) Arrow Functions: **do not have their own `this`**; they lexically inherit `this` from enclosing scope.
Purpose: Allows functions to operate dynamically on different target object contexts.
Example: How `this` differs between regular methods and arrow functions inside object timers.
const user = { name: "Somesh", regularFunc: function() { console.log(this.name); }, // "Somesh" arrowFunc: () => { console.log(this.name); } // undefined (lexical window scope) };
Task: Explain in your notebook why arrow functions should NOT be used as object methods or prototype methods.

12. Method Borrowing: `call()`, `apply()` & `bind()`

Meaning: Explicitly controlling and overriding the `this` context binding of any function.
Definition: `call(thisArg, arg1, arg2)`: Invokes function immediately with explicit `this` and individual arguments. `apply(thisArg, [argsArray])`: Invokes function immediately accepting arguments as an Array. `bind(thisArg)`: Returns a **new bound function** with fixed `this` for later invocation.
Purpose: Enables method borrowing between objects and preserving `this` context in async event callbacks.
Example: Borrowing a greeting method for a different person object.
const person1 = { name: "Somesh" }; const person2 = { name: "Aarav" }; function greet(city, country) { console.log(`Hello ${this.name} from ${city}, ${country}`); } // Explicit binding: greet.call(person1, "Mumbai", "India"); greet.apply(person2, ["Delhi", "India"]); // Bound function for later: const boundGreet = greet.bind(person1, "Pune", "India"); boundGreet();
Task: Write a script borrowing `Array.prototype.slice.call()` to convert an `arguments` object into a real array.

📅 Lecture 05 | Module 05: Memory Management, Performance & DOM Patterns Day 5

13. Memory Management & Garbage Collection

Meaning: How JavaScript automatically allocates and reclaims memory using garbage collection algorithms.
Definition: Uses the **Mark-and-Sweep Algorithm**. The engine starts at global root objects, "marks" all reachable objects, and "sweeps" unreferenced/unreachable memory blocks to free memory.
Purpose: Ensures efficient RAM utilization during long-running web application sessions.
Example: Setting an object reference to `null` to make it eligible for garbage collection.
let data = { hugeArray: new Array(1000000) }; // Process data... data = null; // Unreachable -> Swept by Garbage Collector
Task: Explain the Mark-and-Sweep garbage collection algorithm step-by-step in your notebook.

14. Identifying & Preventing Memory Leaks

Meaning: Memory that is no longer needed by the application but is not returned to the operating system or pool.
Definition: Common causes: 1) Accidental global variables. 2) Forgotten `setInterval` timers. 3) Unremoved DOM event listeners. 4) Detached DOM nodes held in closures.
Purpose: Prevents web browser tabs from slowing down, freezing, or crashing due to RAM consumption growth.
Example: A forgotten interval timer leaking memory.
// LEAK RISK: function startLeak() { const hugeData = new Array(1000000); setInterval(() => { console.log(hugeData.length); // Closure keeps hugeData in memory forever! }, 1000); }
Task: List 4 common sources of JavaScript memory leaks and write the code fix for each.

15. Performance Optimization: Debouncing

Meaning: A rate-limiting technique that delays executing a function until a specified time delay has elapsed since the user last triggered the event.
Definition: Every new event trigger resets the internal timer (`clearTimeout`). The target callback executes ONLY after the user stops triggering events for the specified delay duration.
Purpose: Optimizes search input fields, auto-save triggers, and window resize listeners to prevent spamming server APIs.
Example: Debouncing a search input field by 300ms.
function debounce(fn, delay) { let timer; return function(...args) { clearTimeout(timer); timer = setTimeout(() => fn.apply(this, args), delay); }; } const handleSearch = debounce((query) => { console.log("Fetching API for:", query); }, 300);
Task: Implement a debounced search input field that logs the value 500ms after user stops typing.

16. Performance Optimization: Throttling

Meaning: A rate-limiting technique that enforces a maximum frequency rate at which a function can execute over time.
Definition: Ensures a function executes at most **once every X milliseconds**, regardless of how many times the user triggers the event.
Purpose: Optimizes high-frequency continuous events like scroll position monitoring, infinite scroll triggers, and button click spamming.
Example: Throttling window scroll event listeners.
function throttle(fn, limit) { let inThrottle = false; return function(...args) { if (!inThrottle) { fn.apply(this, args); inThrottle = true; setTimeout(() => inThrottle = false, limit); } }; } const handleScroll = throttle(() => { console.log("Scroll position calculated!"); }, 1000);
Task: Explain in your notebook when to choose Debouncing versus when to choose Throttling.

17. Event Delegation Pattern

Meaning: A DOM performance pattern where a single event listener is attached to a parent container to manage events for all current and future child elements.
Definition: Leverages **Event Bubbling** (events propagating up the DOM tree). The parent listener inspects `event.target` to handle clicks for child elements dynamically.
Purpose: Reduces memory footprint by avoiding attaching hundreds of separate event listeners to dynamic list items.
Example: Handling list item clicks via a single parent `
    ` listener.
const list = document.querySelector('#todo-list'); // Single event listener on parent! list.addEventListener('click', (event) => { if (event.target.tagName === 'BUTTON') { console.log("Deleted item:", event.target.parentElement.innerText); } });
Task: Create a dynamic list where clicking a "Delete" button removes the row using Event Delegation on the parent list.
