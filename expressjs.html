📅 Lecture 01 | Module 01: Intro, Environment & First Server Day 1

1. Introduction to Express JS

Meaning: A fast, unopinionated, minimalist web framework for NodeJS.
Definition: Express provides a thin layer of fundamental web application features (routing, middleware, HTTP utilities) on top of Node's built-in `http` module without obscuring Node features.
Purpose: Simplifies building robust web applications, RESTful APIs, and microservices in JavaScript.
Example: Writing clean route handlers in Express vs manual `if-else` URL checks in raw Node HTTP.
// Express replaces complex raw Node http.createServer logic const express = require('express'); const app = express();
Task: Explain in your notebook 3 main advantages of using ExpressJS over raw Node.js `http` module.

2. Express Environment & Installation

Meaning: Initializing a NodeJS environment and installing the Express framework package via NPM.
Definition: Created by initializing a `package.json` file (`npm init -y`) and installing Express (`npm install express`). Package dependencies are managed in `node_modules`.
Purpose: Sets up the required dependency tree to build Express server applications.
Example: Installing Express and Nodemon for auto-reloading server development.
mkdir express-app cd express-app npm init -y npm install express npm install --save-dev nodemon
Task: Create a project folder, install `express` and `nodemon`, and configure a `"start"` script in `package.json`.

3. Printing Your First "Hello World" Server

Meaning: Instantiating an Express application and listening for HTTP GET requests on a specific port.
Definition: `app.get('/', callback)` defines a route handler for root HTTP GET requests. `app.listen(port)` starts the web server socket.
Purpose: Establishes the minimal baseline boilerplate for any Express application server.
Example: Running an Express server listening on port 3000.
const express = require('express'); const app = express(); const PORT = 3000; app.get('/', (req, res) => { res.send('Hello World from ExpressJS!'); }); app.listen(PORT, () => { console.log(`Server running on http://localhost:${PORT}`); });
Task: Write an Express app that serves "Hello World" on port 4000 and test it in your browser.

📅 Lecture 02 | Module 02: Routing, HTTP Methods & Resource Building Day 2

4. Express Routing & Redirection

Meaning: Defining how an application responds to client requests to particular endpoints (URIs) and redirecting requests.
Definition: Routes are defined as `app.METHOD(PATH, HANDLER)`. `res.redirect('/new-path')` redirects client browsers to a different URL endpoint.
Purpose: Navigates clients to appropriate server logic and forwards outdated URLs to updated destinations.
Example: Redirecting `/old-home` to `/` root route.
app.get('/home', (req, res) => { res.send('Home Page'); }); // Redirection app.get('/old-home', (req, res) => { res.redirect('/home'); });
Task: Create routes `/about` and `/contact`, and redirect `/help` to `/contact`.

5. HTTP Methods (GET, POST, PUT, DELETE)

Meaning: Standard request methods indicating the desired action to be performed on a given server resource.
Definition: **GET** (retrieve data), **POST** (create new resource), **PUT** (update existing resource completely), **DELETE** (remove resource).
Purpose: Forms the foundational protocol for RESTful web service communication.
Example: Mapping CRUD operations to HTTP methods on `/api/users`.
app.get('/api/users', (req, res) => res.send('Get all users')); app.post('/api/users', (req, res) => res.send('Create new user')); app.put('/api/users/:id', (req, res) => res.send('Update user')); app.delete('/api/users/:id', (req, res) => res.send('Delete user'));
Task: Write 4 Express route handlers using GET, POST, PUT, and DELETE on `/api/products`.

6. Resource & URL Building (Route Params & Query Params)

Meaning: Extracting dynamic parameter variables and search query values from incoming request URLs.
Definition: **Route Parameters** (`/users/:id`) are captured in `req.params`. **Query Parameters** (`/search?q=phone`) are captured in `req.query`.
Purpose: Enables fetching specific single resources by ID or filtering list results by search terms.
Example: Accessing user ID parameter and search category query parameter.
// Route Parameter: /users/101 app.get('/users/:id', (req, res) => { res.send(`User ID requested: ${req.params.id}`); }); // Query Parameter: /search?category=shoes app.get('/search', (req, res) => { res.send(`Searching in category: ${req.query.category}`); });
Task: Write a route `/products/:category/:id` and log both parameters from `req.params`.

📅 Lecture 03 | Module 03: Middleware, Templating, Form Data & Static Files Day 3

7. Express Middleware Architecture

Meaning: Functions that have access to the Request object (`req`), Response object (`res`), and the `next` function in the request-response cycle.
Definition: Middleware can execute code, make changes to `req`/`res`, end request cycle, or call `next()` to pass control to the next middleware function.
Purpose: Used for logging, authentication checks, parsing request bodies, CORS handling, and security.
Example: Creating a custom logger middleware.
const logger = (req, res, next) => { console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`); next(); // Move to next handler }; app.use(logger); // Application-level middleware
Task: Write a custom middleware function that logs client IP address for every request.

8. Templating Engines (EJS / Pug)

Meaning: Server-side rendering tools that replace variables in HTML template files with actual dynamic data.
Definition: Configured using `app.set('view engine', 'ejs')`. Views are placed in a `/views` folder and rendered using `res.render('viewName', { data })`.
Purpose: Enables rendering dynamic server-driven HTML web pages.
Example: Rendering an EJS view with server variables.
app.set('view engine', 'ejs'); app.get('/profile', (req, res) => { res.render('profile', { username: 'Somesh Hadve', role: 'Instructor' }); });
Task: Install `ejs`, create a view `index.ejs`, and render a list of items passed from your Express route.

9. Handling Form Data (`express.urlencoded` & `express.json`)

Meaning: Built-in Express middleware required to parse incoming request payloads into `req.body`.
Definition: `express.json()` parses incoming JSON payloads from API clients. `express.urlencoded({ extended: true })` parses incoming HTML form submissions.
Purpose: Without body parser middleware, `req.body` remains `undefined` when receiving form POST requests.
Example: Parsing POST body payload from an HTML form.
app.use(express.json()); app.use(express.urlencoded({ extended: true })); app.post('/login', (req, res) => { const { email, password } = req.body; res.send(`Logging in user: ${email}`); });
Task: Write a POST route `/contact` that reads `name` and `message` from `req.body` and returns a confirmation JSON.

10. Serving Static Files (`express.static`)

Meaning: Serving static assets like images, CSS stylesheets, and client-side JavaScript files directly to browsers.
Definition: `express.static(folderName)` is a built-in middleware. Files inside the specified directory (e.g., `/public`) are served at the root URL.
Purpose: Delivers client-side CSS, logos, and JavaScript bundles without requiring explicit routes for every asset file.
Example: Serving all files inside a `public` directory.
const path = require('path'); // Serve static assets from 'public' folder app.use(express.static(path.join(__dirname, 'public')));
Task: Create a `public` folder, place `style.css` and a logo image inside it, and serve them using `express.static`.

📅 Lecture 04 | Module 04: Database CRUD, Cookies, Sessions & Auth Day 4

11. Database CRUD in Express (MongoDB / MySQL)

Meaning: Connecting Express route handlers to persistent database storage engines to execute CRUD operations.
Definition: Express routes interact with database drivers or ORMs/ODMs (like Mongoose or MySQL2) inside async route handlers to create, read, update, and delete records.
Purpose: Powers persistent web application backends.
Example: Async Express route creating a record in a database.
app.post('/api/products', async (req, res) => { try { const newProduct = await Product.create(req.body); res.status(201).json(newProduct); } catch (err) { res.status(400).json({ error: err.message }); } });
Task: Write an async Express route that queries a database and returns all records as JSON with status 200 OK.

12. Cookies & Session Management

Meaning: Preserving user state and session data across stateless HTTP requests.
Definition: **Cookies** (`cookie-parser`) store small key-value strings on client browsers. **Sessions** (`express-session`) store session state on the server and store only a encrypted session ID cookie on the client.
Purpose: Remembers user login state, shopping cart contents, and preferences across page reloads.
Example: Configuring `express-session` middleware.
const session = require('express-session'); app.use(session({ secret: 'supersecretkey', resave: false, saveUninitialized: true, cookie: { maxAge: 60000 } }));
Task: Set up `express-session` and track page view visit counts for a user (`req.session.views`).

13. Authentication: Send, Receive & Validate Data

Meaning: Verifying user identity credentials (email/password) and securing private endpoints.
Definition: Involves receiving credentials in `req.body`, validating input schemas, comparing hashed passwords (`bcrypt`), and issuing authentication tokens (JWT) or setting session cookies.
Purpose: Restricts access to sensitive routes and user account dashboards.
Example: Basic login credential verification route.
app.post('/api/login', async (req, res) => { const { email, password } = req.body; if (!email || !password) { return res.status(400).json({ error: "Email & Password required!" }); } // Validate credentials... res.json({ message: "Login successful!" }); });
Task: Create a login validation middleware that verifies `req.body.email` contains an `@` symbol.

📅 Lecture 05 | Module 05: RESTful API, Error Handling & Debugging Day 5

14. RESTful API Architecture

Meaning: Designing standardized web service endpoints that communicate using JSON payloads and standard HTTP status codes.
Definition: Uses predictable resource endpoints (`/api/v1/products`), appropriate HTTP methods (GET, POST, PUT, DELETE), and standard HTTP status codes (`200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`, `500 Server Error`).
Purpose: Connects React, Angular, NextJS, or Mobile front-end applications to Express backends cleanly.
Example: Returning structured JSON API response with status codes.
app.get('/api/v1/items/:id', (req, res) => { const item = findItem(req.params.id); if (!item) { return res.status(404).json({ success: false, message: "Item not found" }); } res.status(200).json({ success: true, data: item }); });
Task: Design a complete RESTful CRUD API endpoint for `/api/v1/books` handling GET, POST, and DELETE.

15. Error Handling & Debugging in Express

Meaning: Catching synchronous and asynchronous runtime errors centrally and returning formatted error responses to clients.
Definition: Express error-handling middleware takes **4 arguments**: `(err, req, res, next)`. Placed at the very end of the middleware stack after all routes.
Purpose: Prevents server crashes on unexpected errors and hides sensitive stack traces from production clients.
Example: Global Express error handling middleware.
// Catch-all 404 Route app.use((req, res, next) => { res.status(404).json({ error: "Route not found" }); }); // Global Error Handler app.use((err, req, res, next) => { console.error(err.stack); res.status(err.status || 500).json({ success: false, message: err.message || "Internal Server Error" }); });
Task: Add a 404 handler and a global 4-argument error handling middleware to your Express app.
