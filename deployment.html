📅 Lecture 01 | Module 01: Git and GitHub Foundations Day 1

1. Introduction to Web Deployment

Meaning: Deployment is the process of publishing a locally developed application to a server so that users can access it through the internet.
Definition: Web deployment includes preparing a production build, configuring a hosting server, uploading application files, connecting databases, setting environment variables, and exposing the application through a public URL.
Purpose: It converts a project running only on a developer's computer into a publicly accessible and maintainable production application.
Example: A React project running at localhost:5173 can be deployed to Vercel and accessed through a public HTTPS address.
Development: http://localhost:5173 Production: https://my-project.vercel.app
Task: Write down the major stages between completing a local application and publishing it on the internet.

2. Git Version Control

Meaning: Git is a distributed version-control system that records changes made to project files over time.
Definition: Git creates a local repository in which developers can stage changes, create commits, work with branches, compare versions, and restore older code when necessary.
Purpose: It protects project history, supports teamwork, and makes it possible to experiment safely without permanently damaging stable code.
Example: A developer creates a feature branch, completes a login page, commits the work, and merges it into the main branch.
git init git status git add . git commit -m "Create initial project structure" git log --oneline
Task: Initialize Git in a sample project, create two commits, and inspect the commit history with git log --oneline.

3. GitHub Repositories and Remote Workflow

Meaning: GitHub is a cloud platform used to store Git repositories and collaborate on software projects.
Definition: A remote repository is an online copy of a local Git repository. Developers use push to upload commits, pull to download and merge changes, and clone to create a local copy.
Purpose: It provides cloud backup, team collaboration, pull requests, issue tracking, code review, and integration with deployment platforms.
Example: Vercel or Render can monitor the main branch of a GitHub repository and deploy automatically after every push.
git remote add origin https://github.com/username/project.git git branch -M main git push -u origin main # Download later: git clone https://github.com/username/project.git
Task: Create a GitHub repository, connect it to a local project, and push the main branch successfully.

📅 Lecture 02 | Module 02: Front-End Hosting and Production Builds Day 2

4. Production Build Process

Meaning: A production build converts development source code into optimized files intended for real users.
Definition: Build tools bundle modules, minify JavaScript and CSS, optimize assets, remove unused code, create hashed filenames, and place the final files inside folders such as dist or build.
Purpose: It reduces file sizes and improves application speed, browser caching, stability, and loading performance.
Example: Vite produces a dist folder after running npm run build.
# React with Vite npm run build npm run preview # Angular ng build --configuration production # Next.js npm run build npm run start
Task: Create a production build of one front-end project and inspect the generated files and their sizes.

5. Static Front-End Deployment

Meaning: Static deployment publishes HTML, CSS, JavaScript, fonts, and images without requiring a continuously running backend process.
Definition: Services such as GitHub Pages, Netlify, and Vercel host static files on global Content Delivery Networks. They can build projects directly from connected Git repositories.
Purpose: It is an inexpensive and fast method for deploying portfolios, landing pages, documentation, and client-rendered front-end applications.
Example: A pure HTML/CSS portfolio can be hosted on GitHub Pages, while a Vite React project can be imported into Vercel.
# Typical Vite deployment settings: Build Command: npm run build Output Directory: dist # Typical Create React App settings: Build Command: npm run build Output Directory: build
Task: Deploy one HTML/CSS website to GitHub Pages or Netlify and verify that images, links, and styles work correctly.

6. Single Page Application Route Rewrites

Meaning: A route rewrite sends unknown front-end routes back to the application's main HTML file.
Definition: In React or Angular SPAs, routes such as /products/5 are handled in the browser. The hosting server must return index.html instead of generating a 404 error when the route is refreshed.
Purpose: It ensures client-side routes continue to work after a direct URL visit or browser refresh.
Example: Netlify uses a redirects file to rewrite every route to /index.html.
# File: public/_redirects /* /index.html 200 # Vercel example: vercel.json { "rewrites": [ { "source": "/(.*)", "destination": "/index.html" } ] }
Task: Deploy an SPA with at least two routes and verify that refreshing the second route does not produce a 404 error.

📅 Lecture 03 | Module 03: Backend Hosting and Environment Variables Day 3

7. Backend Server Deployment

Meaning: Backend deployment runs server-side application code continuously on a cloud platform.
Definition: A cloud service installs dependencies, executes a start command, assigns a public URL, and forwards internet requests to the application through a dynamically assigned port.
Purpose: It makes REST APIs, authentication services, database operations, and server-rendered applications available to remote front-end clients.
Example: An Express API can be deployed to Render and started with npm start.
const express = require('express'); const app = express(); const PORT = process.env.PORT || 3000; app.get('/api/health', (req, res) => { res.status(200).json({ status: 'Server is healthy' }); }); app.listen(PORT, () => { console.log(`Server listening on port ${PORT}`); });
Task: Add a health-check route to an Express server and deploy the API to Render or another Node-compatible platform.

8. Environment Variables and Secret Management

Meaning: Environment variables store configuration values outside the application's source code.
Definition: Secrets such as database URLs, API keys, JWT secrets, and production flags are provided by the operating system or deployment platform and accessed through objects such as process.env.
Purpose: It prevents sensitive credentials from being committed to public repositories and allows different settings for development, testing, and production.
Example: A local .env file contains a database URI and is ignored by Git.
# .env PORT=5000 DATABASE_URL=mongodb+srv://username:password@cluster.example.net/app JWT_SECRET=replace_with_a_strong_secret # NodeJS require('dotenv').config(); console.log(process.env.PORT); # .gitignore .env node_modules/
Task: Move a hardcoded database URL into a .env file, add the file to .gitignore, and read it safely in the application.

9. CORS and Front-End/Backend Connection

Meaning: Cross-Origin Resource Sharing controls whether a browser permits one website origin to request resources from another origin.
Definition: An origin is defined by protocol, domain, and port. A backend uses response headers such as Access-Control-Allow-Origin to authorize trusted front-end applications.
Purpose: It allows a deployed front end and a separately hosted API to communicate while blocking unauthorized browser origins.
Example: An API on Render allows requests only from a React application hosted on Vercel.
const cors = require('cors'); app.use(cors({ origin: 'https://my-frontend.vercel.app', methods: ['GET', 'POST', 'PUT', 'DELETE'], credentials: true }));
Task: Configure CORS so that only your deployed front-end domain can access your Express API.

📅 Lecture 04 | Module 04: Cloud Databases, Domains, DNS and HTTPS Day 4

10. Cloud Database Deployment

Meaning: Cloud database deployment stores production application data on a managed remote database service.
Definition: Managed services such as MongoDB Atlas, Neon, Supabase, Railway, and cloud MySQL providers handle server availability, connection credentials, backups, security rules, and scaling.
Purpose: It gives deployed backend servers reliable access to persistent data without depending on a developer's local XAMPP or MongoDB service.
Example: An Express API connects to MongoDB Atlas through a URI stored in DATABASE_URL.
const mongoose = require('mongoose'); async function connectDatabase() { try { await mongoose.connect(process.env.DATABASE_URL); console.log('Cloud database connected'); } catch (error) { console.error('Database connection failed:', error.message); process.exit(1); } } connectDatabase();
Task: Create a free cloud database, add its connection string as a platform secret, and verify the connection from your deployed backend.

11. Domain Names and DNS Records

Meaning: A domain is a human-readable website address, while DNS maps that address to hosting infrastructure.
Definition: Important DNS records include A records for IPv4 addresses, AAAA for IPv6, CNAME for aliases, MX for mail servers, and TXT for verification and security policies.
Purpose: DNS allows users to access a service using a memorable address instead of a numerical server IP or platform-generated URL.
Example: The subdomain api.example.com can use a CNAME record pointing to a hosted backend service.
Example DNS records: A @ 192.0.2.10 CNAME www example.vercel-dns.com CNAME api my-api.onrender.com TXT @ platform-verification-code
Task: Draw a request flow showing how a browser uses DNS to locate a server after the user enters a domain name.

12. HTTPS, SSL/TLS Certificates and Security

Meaning: HTTPS is the secure version of HTTP that encrypts communication between clients and servers.
Definition: TLS certificates verify a domain's identity and encrypt request/response data. Modern hosting platforms commonly issue and renew free certificates through services such as Let's Encrypt.
Purpose: It protects passwords, tokens, payment information, form data, and API responses against interception or modification.
Example: A browser displays a secure padlock after the domain receives a valid certificate and redirects HTTP requests to HTTPS.
HTTP: http://example.com HTTPS: https://example.com Recommended production redirect: http://example.com --- 301 ---> https://example.com
Task: Inspect a live website's TLS certificate in the browser and record the issuer, validity dates, and secured domain.

📅 Lecture 05 | Module 05: Docker, CI/CD and Monitoring Day 5

13. Docker Containers

Meaning: Docker packages an application and its dependencies into a portable container.
Definition: A Docker image is an immutable application template built from a Dockerfile. A container is a running instance of that image with isolated processes, networking, and filesystem layers.
Purpose: It ensures that an application runs consistently across development computers, testing servers, and production environments.
Example: A Node application and its exact Node runtime can be packaged into an image and started on any Docker-compatible server.
# Dockerfile FROM node:20-alpine WORKDIR /app COPY package*.json ./ RUN npm ci --omit=dev COPY . . ENV NODE_ENV=production EXPOSE 3000 CMD ["npm", "start"]
Task: Write a Dockerfile for an Express API, build its image, and run it locally on port 3000.

14. CI/CD Pipeline

Meaning: Continuous Integration and Continuous Delivery automate code verification and deployment.
Definition: CI automatically installs dependencies, runs formatting checks, tests, and builds after code changes. CD automatically releases verified code to staging or production environments.
Purpose: It reduces manual deployment errors, catches bugs early, and allows teams to release software safely and frequently.
Example: A GitHub Actions workflow runs tests after every push to the main branch.
# File: .github/workflows/ci.yml name: Node CI on: push: branches: [main] pull_request: branches: [main] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 20 - run: npm ci - run: npm test - run: npm run build --if-present
Task: Create a GitHub Actions workflow that installs dependencies and runs the project's test command after every push.

15. Production Logging, Monitoring and Health Checks

Meaning: Monitoring observes whether a live application is available, fast, and free from critical errors.
Definition: Production observability commonly includes structured logs, uptime checks, health endpoints, error tracking, CPU and memory metrics, database monitoring, and alert notifications.
Purpose: It helps developers identify failures quickly, understand their cause, and restore service before many users are affected.
Example: An uptime monitor requests /api/health every five minutes and sends an alert when the server returns an error.
app.get('/api/health', async (req, res) => { res.status(200).json({ status: 'ok', uptimeSeconds: process.uptime(), timestamp: new Date().toISOString(), environment: process.env.NODE_ENV || 'development' }); });
Task: Add a JSON health endpoint to a backend and configure a free uptime monitor to check its public URL.
