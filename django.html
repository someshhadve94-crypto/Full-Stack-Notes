1. Intro to Django & Framework Architecture

Meaning: A high-level, "batteries-included" Python web framework that enables rapid development of secure and maintainable websites.
Definition: Django handles core backend functionality out of the box — including ORM, admin dashboard, user authentication, URL routing, security against CSRF/SQLi, and template rendering.
Purpose: Eliminates repetitive boilerplate code so developers can move from concept to launch rapidly.
Example: Instagram, Spotify, Disque, and Pinterest use Django for their server backend.

2. Django Installation & Virtual Environment

Meaning: Setting up an isolated Python environment and installing the Django package using PIP.
Definition: `python -m venv venv` creates an isolated environment. Activating it ensures project dependency versions do not conflict globally. Django is installed via `pip install django`.
Purpose: Ensures project reproducibility and clean dependency management across local and production machines.
Example: Checking installed Django version with `python -m django --version`.
python -m venv venv # Windows: venv\Scripts\activate # Mac/Linux: source venv/bin/activate pip install django
Task: Create a virtual environment, activate it, install Django, and print the installed version.

3. Creating First Django Project

Meaning: Initializing a root Django project folder structure containing configurations.
Definition: Executed via `django-admin startproject project_name`. Starts the development server using `python manage.py runserver`.
Purpose: Creates the master entry point and configuration repository for the web application.
Example: Running server on `http://127.0.0.1:8000/` and seeing Django's default rocket launch screen.
django-admin startproject mywebsite cd mywebsite python manage.py runserver
Task: Create a Django project `mywebsite`, start the local development server, and view it in Chrome.

4. Django Project Structure Explanation

Meaning: Understanding the purpose of default generated project files.
Definition: `manage.py`: Command-line tool to manage project. `settings.py`: Master configurations (DB, installed apps, media, static files). `urls.py`: Global routing dispatcher. `wsgi.py` / `asgi.py`: Web server deployment entry points.
Purpose: Provides modular, predictable project organization across all Django applications.
Example: Configuring `ALLOWED_HOSTS` or database credentials in `settings.py`.
# mywebsite/ # ├── manage.py # └── mywebsite/ # ├── __init__.py # ├── settings.py # ├── urls.py # ├── asgi.py # └── wsgi.py
Task: Open `settings.py` and explain the function of `INSTALLED_APPS` and `DATABASES`.

📅 Lecture 02 | Module 02: Project vs App & MVT Architecture Day 2

5. Creating First Django App

Meaning: Generating a standalone, self-contained sub-module focused on a specific feature set.
Definition: Generated using `python manage.py startapp app_name`. Creates `views.py`, `models.py`, `admin.py`, `apps.py`, and `tests.py`. Must be registered in `settings.py` under `INSTALLED_APPS`.
Purpose: Promotes modular code reuse across multiple projects.
Example: Creating a `blog` app or `accounts` app inside an e-commerce project.
python manage.py startapp blog # Inside settings.py: INSTALLED_APPS = [ ... 'blog', ]

6. Project VS App Difference

Meaning: Distinguishing between the overall website container and individual feature modules.
Definition: A **Project** is the entire web application composed of global configurations and multiple apps. An **App** is a portable, modular Web application that performs a specific function (e.g., Blog, Forum, User Auth).
Purpose: Keeps large enterprise codebases modular, organized, and pluggable.
Example: Project = E-Commerce Site; Apps = `cart`, `payment`, `inventory`, `users`.
# 1 Project (e_commerce) = Many Apps (users + products + orders + billing)

7. MVT Architecture (Model - View - Template)

Meaning: Django's variation of the classic MVC (Model-View-Controller) design pattern.
Definition: Model: Manages data structure and database schema. View: Business logic that receives HTTP requests, interacts with Models, and renders Templates. Template: Presentation layer (HTML mixed with Django Template Language). Django framework acts as the Controller.
Purpose: Enforces complete separation of concerns between database logic, business logic, and UI display.
Example: URL -> View checks Model -> View renders Template -> Client receives HTML response.
# Client Request ---> urls.py ---> views.py <---> models.py (DB) # | # v # templates/ (HTML) ---> Client Response
Task: Draw the Django MVT request-response lifecycle flowchart in your notebook.

8. Views & URL Dispatcher Example

Meaning: Handling HTTP requests and returning HTTP responses via mapped URLs.
Definition: A View is a Python function/class accepting an `HttpRequest` object and returning an `HttpResponse` or rendered template. `urls.py` uses `path()` to map URL endpoints to Views.
Purpose: Routes user web requests to the correct Python logic handler.
Example: Returning a "Hello World" text response when visiting `/home/`.
# blog/views.py from django.http import HttpResponse def home(request): return HttpResponse("<h1>Welcome to Somesh Hadve's Blog!</h1>") # mywebsite/urls.py from django.urls import path from blog.views import home urlpatterns = [ path('home/', home), ]

📅 Lecture 03 | Module 03: Database, Models, Migrations & Templates Day 3

9. Django Database Configuration (SQLite & MySQL)

Meaning: Configuring backend database engines inside `settings.py`.
Definition: Defaults to zero-config SQLite (`db.sqlite3`). Can be switched to MySQL using `django.db.backends.mysql` with `NAME`, `USER`, `PASSWORD`, `HOST`, and `PORT`.
Purpose: Connects Django's ORM seamlessly to development or production databases.
Example: Switching settings from default SQLite to local XAMPP MySQL.
# settings.py DATABASES = { 'default': { 'ENGINE': 'django.db.backends.mysql', 'NAME': 'django_db', 'USER': 'root', 'PASSWORD': '', 'HOST': 'localhost', 'PORT': '3306', } }
Task: Connect your Django project to a local MySQL database created in XAMPP.

10. Django Models (ORM)

Meaning: Defining database tables using pure Python classes without writing raw SQL.
Definition: Classes inheriting from `models.Model`. Class attributes represent database table columns defined by field types (`CharField`, `IntegerField`, `TextField`, `DateTimeField`, `ForeignKey`).
Purpose: Provides Object-Relational Mapping (ORM) to query databases using Python objects safely.
Example: Defining a `Article` model.
# blog/models.py from django.db import models class Article(models.Model): title = models.CharField(max_length=200) content = models.TextField() created_at = models.DateTimeField(auto_now_add=True) def __str__(self): return self.title
Task: Create a `Product` model with `name`, `price`, `stock`, and `description` fields.

11. Database Migrations

Meaning: Translating Python Model changes into executable database SQL schema updates.
Definition: Two-step process: 1) `python manage.py makemigrations` creates migration blueprint files. 2) `python manage.py migrate` applies those blueprints to create/alter database tables.
Purpose: Version-controls database schema alterations safely across team environments.
Example: Creating database tables after defining new models.
python manage.py makemigrations python manage.py migrate
Task: Run migrations on your project and verify created tables inside phpMyAdmin or SQLite viewer.

12. Django Templates & Template Language (DTL)

Meaning: Dynamic HTML files enriched with Python-like variables and control tags.
Definition: Rendered via `render(request, 'template.html', context)`. Uses `{{ variable }}` for values, `{% for %}`, `{% if %}` for logic loops/conditions, and template inheritance (`{% extends %}`, `{% block %}`).
Purpose: Generates dynamic client-side HTML pages rendered directly by the server.
Example: Rendering a list of database articles inside HTML.
<!-- templates/articles.html --> <h1>Article List</h1> <ul> {% for article in articles %} <li>{{ article.title }} - {{ article.created_at }}</li> {% endfor %} </ul>

📅 Lecture 04 | Module 04: Authentication, CBV & Admin Customization Day 4

13. Django Authentication System

Meaning: Built-in user management framework handling registration, login, logout, and password hashing.
Definition: Uses `django.contrib.auth` models (`User`), forms (`UserCreationForm`, `AuthenticationForm`), and views (`login`, `logout`, `@login_required` decorator).
Purpose: Provides production-ready, highly secure user authentication out of the box.
Example: Protecting a dashboard view so only logged-in users can access it.
from django.contrib.auth.decorators import login_required from django.contrib.auth import authenticate, login, logout @login_required def dashboard(request): return render(request, 'dashboard.html')
Task: Build a user signup and login page using Django's built-in `UserCreationForm`.

14. Class-Based Views (CBV) vs Function-Based Views (FBV)

Meaning: Two different architectural styles for structuring Django View business logic.
Definition: **FBVs** are explicit Python functions handling requests via `if request.method == 'POST':`. **CBVs** use object-oriented Python classes (`ListView`, `DetailView`, `CreateView`, `UpdateView`, `DeleteView`) to reuse common CRUD patterns.
Purpose: CBVs drastically reduce code lines for standard database CRUD operations.
Example: Displaying a list using `ListView` CBV.
from django.views.generic import ListView from .models import Article class ArticleListView(ListView): model = Article template_name = 'article_list.html' context_object_name = 'articles'
Task: Re-write a product listing view using Django's generic `ListView` Class-Based View.

15. Django Admin Customization

Meaning: Customizing Django's automatic built-in administrative dashboard interface.
Definition: Created using `python manage.py createsuperuser`. Models are registered in `admin.py` using `admin.site.register()` or `ModelAdmin` classes (`list_display`, `search_fields`, `list_filter`).
Purpose: Gives site administrators an instant CMS dashboard to manage database records visually.
Example: Adding search bars and column filters to the Admin panel for Products.
# blog/admin.py from django.contrib import admin from .models import Article @admin.register(Article) class ArticleAdmin(admin.ModelAdmin): list_display = ('title', 'created_at') search_fields = ('title', 'content') list_filter = ('created_at',)

📅 Lecture 05 | Module 05: File Uploads, Testing & Deployment Day 5

16. File Upload & Media Handling

Meaning: Managing user-uploaded static assets like profile images or PDF documents.
Definition: Requires `ImageField` or `FileField` in models (needs `Pillow` library). HTML forms must include `enctype="multipart/form-data"`. Configured via `MEDIA_URL` and `MEDIA_ROOT` in `settings.py`.
Purpose: Allows users to upload avatars, product thumbnails, or attachments safely.
Example: Adding a product image field to a model.
# settings.py MEDIA_URL = '/media/' MEDIA_ROOT = BASE_DIR / 'media' # models.py image = models.ImageField(upload_to='products/') # HTML Form <form method="POST" enctype="multipart/form-data">
Task: Install `Pillow`, add an `image` field to your Product model, and render the uploaded image on screen.

17. Django Testing

Meaning: Writing automated unit tests to verify application views, models, and URLs.
Definition: Written inside `tests.py` using Django's built-in `TestCase` class. Executed via command `python manage.py test`.
Purpose: Ensures code stability and catches regressions before shipping updates to production.
Example: Testing if a HTTP GET request returns status code 200 OK.
# blog/tests.py from django.test import TestCase class HomePageTest(TestCase): def test_home_page_status_code(self): response = self.client.get('/home/') self.assertEqual(response.status_code, 200)
Task: Write a unit test that verifies your `/about/` page returns HTTP status 200 OK.

18. Django Deployment Basics

Meaning: Publishing a Django application to live cloud servers (Heroku, Render, AWS, PythonAnywhere).
Definition: Involves setting `DEBUG = False`, configuring `ALLOWED_HOSTS`, collecting static files using `python manage.py collectstatic`, using WSGI servers like `Gunicorn`, and securing secrets with environment variables.
Purpose: Makes your application publicly accessible on the internet securely.
Example: Production settings preparation.
# settings.py for production: DEBUG = False ALLOWED_HOSTS = ['yourdomain.com', 'localhost'] STATIC_ROOT = BASE_DIR / 'staticfiles'
Task: Prepare your Django app for production by setting up static root and running `collectstatic`.
