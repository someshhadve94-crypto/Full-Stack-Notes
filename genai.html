1. Introduction to Generative AI vs Discriminative AI

Meaning: The distinction between Artificial Intelligence models that generate new content versus those that classify existing data.
Definition: **Discriminative AI** models evaluate conditional probabilities `P(Y|X)` to classify or predict labels (e.g., spam vs ham, object detection). **Generative AI** models learn joint probability distributions `P(X,Y)` to generate novel text, code, images, audio, or video synthetic data.
Purpose: Enables software engineers to build creative, conversational, and autonomous content generation systems.
Example: Discriminative = Spam Filter / Face Recognition; Generative = ChatGPT, Midjourney, GitHub Copilot.
# Discriminative: Input Data ---> Model ---> Decision / Category Label # Generative: Input Prompt ---> Model ---> Brand New Synthetic Content
Task: Write 3 differences between Discriminative ML models and Generative AI models in your notebook.

2. Large Language Models (LLMs) & Transformer Architecture

Meaning: Deep learning neural network models trained on vast textual datasets using self-attention mechanisms.
Definition: LLMs (GPT-4, Claude, Llama 3) rely on the **Transformer Architecture** (Vaswani et al., 2017). They utilize **Self-Attention** to process entire text sequences in parallel, learning deep contextual relationships between words regardless of distance.
Purpose: Powers natural language understanding, reasoning, translation, code generation, and autonomous agents.
Example: Understanding the word "bank" in "river bank" vs "financial bank" based on surrounding attention context.
# Transformer Self-Attention Formula: # Attention(Q, K, V) = softmax((Q * K^T) / sqrt(d_k)) * V
Task: Draw a simplified diagram of the Transformer Encoder-Decoder architecture in your notebook.

3. Tokens, Context Window & Temperature Parameters

Meaning: The fundamental processing units and hyperparameter controls governing LLM inference behavior.
Definition: **Tokens** are word fragments (~4 characters or 0.75 words). **Context Window** is the maximum token capacity an LLM can process in a single prompt+response session. **Temperature** (0.0 to 1.0) controls randomness/creativity (0.0 = deterministic/fact-based; 1.0 = creative/diverse).
Purpose: Allows developers to fine-tune LLM outputs for precise use cases like strict code generation vs creative writing.
Example: Setting `temperature: 0.0` for SQL generation vs `temperature: 0.8` for brainstorming marketing copy.
// Token Approximation Rule of Thumb: // 1000 Tokens ≈ 750 Words // Low Temp (0.2) -> Consistent, factual, deterministic // High Temp (0.8) -> Creative, varied, surprising

4. Prompt Engineering Techniques (Zero-Shot, Few-Shot & Chain-of-Thought)

Meaning: The practice of structuring textual input queries to guide LLMs toward optimal, accurate outputs.
Definition: **Zero-Shot**: Direct prompt without examples. **Few-Shot**: Including 2-3 input/output examples in the prompt. **Chain-of-Thought (CoT)**: Instructing the LLM to "think step-by-step" before returning its final answer.
Purpose: Significantly increases LLM reasoning accuracy, reduces hallucinations, and enforces output formatting.
Example: Using Chain-of-Thought prompting to solve complex math logic problems.
# Chain-of-Thought Prompt Pattern: Prompt = """ Q: Roger has 5 tennis balls. He buys 2 more cans of 3 balls. How many balls does he have? A: Let's think step by step: 1. Roger starts with 5 balls. 2. 2 cans with 3 balls = 6 balls. 3. 5 + 6 = 11. Answer is 11. Q: [Insert target complex question] A: Let's think step by step: """

5. OpenAI API & SDK Integration (NodeJS / Python)

Meaning: Programmatically connecting web applications to cloud-hosted LLM endpoints using official SDK libraries.
Definition: Uses official client packages (`openai` in Node/Python). Authenticates using API keys passed via environment variables (`process.env.OPENAI_API_KEY`). Calls chat completion endpoints (`openai.chat.completions.create()`).
Purpose: Integrates intelligence directly into custom full-stack web applications, chatbots, and backend services.
Example: Executing a Chat Completion request in NodeJS.
import OpenAI from 'openai'; const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY }); async function generateSummary(text) { const response = await openai.chat.completions.create({ model: 'gpt-4o-mini', messages: [{ role: 'user', content: `Summarize: ${text}` }], temperature: 0.3, }); return response.choices[0].message.content; }

6. Message Roles (System, User, Assistant)

Meaning: The structured conversational context array passed to LLM chat completion APIs.
Definition: **System**: Sets behavioral instructions, persona, and rules. **User**: Represents input from the end-user. **Assistant**: Represents previous responses generated by the LLM model (used to maintain conversation history).
Purpose: Enforces strict guardrails on LLM behavior and preserves multi-turn conversation memory.
Example: Defining a strict coding tutor persona using the System role.
const messages = [ { role: "system", content: "You are a helpful coding assistant. Answer ONLY in clean JavaScript code." }, { role: "user", content: "How do I reverse an array?" }, { role: "assistant", content: "const reversed = arr.reverse();" }, { role: "user", content: "How about without mutating original?" } ];

7. Function Calling & Structured JSON Output

Meaning: Enabling LLMs to output strictly structured JSON schema objects and trigger external backend code functions.
Definition: Developers pass a JSON schema describing available backend functions (`tools`). The LLM detects when a tool should be executed and returns structured JSON arguments instead of text. `response_format: { type: "json_object" }` guarantees valid JSON output.
Purpose: Connects natural language inputs directly to backend database queries, external APIs, and business logic.
Example: Passing a `get_weather(location)` tool definition to the LLM.
const response = await openai.chat.completions.create({ model: "gpt-4o", messages: [{ role: "user", content: "What is the weather in Mumbai?" }], tools: [{ type: "function", function: { name: "get_weather", description: "Get current weather for a city", parameters: { type: "object", properties: { location: { type: "string" } }, required: ["location"] } } }] });

8. LangChain Basics & Chaining Concepts

Meaning: A popular framework designed to simplify building complex applications powered by LLMs.
Definition: LangChain provides abstractions for Prompt Templates, LLM wrappers, Output Parsers, and Sequential Chains (combining multiple LLM calls where output of step A becomes input to step B).
Purpose: Standardizes complex AI pipelines, agentic workflows, and document processing systems.
Example: Creating a PromptTemplate + LLM chain in LangChain.
import { ChatOpenAI } from "@langchain/openai"; import { ChatPromptTemplate } from "@langchain/core/prompts"; const prompt = ChatPromptTemplate.fromTemplate("Explain {topic} in 1 sentence."); const model = new ChatOpenAI({ model: "gpt-4o-mini" }); const chain = prompt.pipe(model); const response = await chain.invoke({ topic: "Docker" });

📅 Lecture 03 | Module 03: Embeddings, Vector DBs & RAG Architecture Day 3

9. Text Embeddings & Vector Representations

Meaning: Converting raw text into dense numerical vector arrays that capture semantic meaning.
Definition: Embedding models (e.g., `text-embedding-3-small`) convert text into high-dimensional vector arrays (e.g., 1536 floating-point numbers). Texts with similar meanings sit close together in vector space measured by **Cosine Similarity**.
Purpose: Powers semantic search, document similarity, recommendation engines, and RAG systems.
Example: "King" - "Man" + "Woman" ≈ "Queen" in vector embedding space.
const embedding = await openai.embeddings.create({ model: "text-embedding-3-small", input: "Full Stack Web Development Notes", }); console.log(embedding.data[0].embedding); // Array of 1536 float numbers

10. Vector Databases (Pinecone, ChromaDB, Pgvector)

Meaning: Specialized database engines optimized to store, index, and query high-dimensional vector embeddings efficiently.
Definition: Uses Approximate Nearest Neighbor (ANN) algorithms (HNSW, IVF) to query millions of vectors in milliseconds. Popular platforms: **Pinecone** (Cloud), **ChromaDB** (Open-Source), **Pgvector** (PostgreSQL extension), **Qdrant**.
Purpose: Serves as the long-term memory store for RAG applications and enterprise knowledge bases.
Example: Querying top 3 most relevant document chunks matching a user query vector.
// Querying Pinecone Vector Store const queryVector = await getEmbedding("How do I setup Django?"); const results = await pineconeIndex.query({ vector: queryVector, topK: 3, includeMetadata: true });

11. Retrieval-Augmented Generation (RAG) Architecture

Meaning: A pattern that enhances LLM responses by retrieving relevant external context data from custom document stores before generating an answer.
Definition: Architecture pipeline: 1) User submits question. 2) Query converted to vector embedding. 3) Vector DB retrieves top matching document chunks. 4) Retrieved chunks injected into LLM System Prompt as context. 5) LLM generates accurate, grounded answer.
Purpose: Eliminates LLM hallucinations, enables querying private company PDFs/data, and bypasses LLM training cutoff limits.
Example: Building a chatbot that answers questions from an internal 200-page HR Policy PDF.
# RAG Pipeline Flow: # Query --> Embedding --> Vector DB Search --> Context Chunks + Query --> LLM --> Grounded Answer

12. Document Chunking & Semantic Search Strategies

Meaning: Splitting large documents into optimal smaller text segments for embedding and retrieval.
Definition: Chunking strategies include Fixed-Size Chunking (e.g., 500 tokens with 50-token overlap) and Recursive Character Text Splitting (splitting by paragraphs, sentences, words). Overlap preserves context across boundaries.
Purpose: Fits retrieved text cleanly inside the LLM context window while maintaining semantic completeness.
Example: Chunking a 50-page PDF manual into 300-word overlapping chunks.
import { RecursiveCharacterTextSplitter } from "langchain/text_splitter"; const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 500, chunkOverlap: 50, }); const docs = await splitter.createDocuments([rawPdfText]);

📅 Lecture 04 | Module 04: AI Agents, Tools & Local Execution Day 4

13. Autonomous AI Agents & Tool Calling (ReAct Framework)

Meaning: Systems where an LLM acts as an autonomous reasoning engine that decides which external tools to call to achieve a goal.
Definition: Uses the **ReAct (Reasoning + Acting)** framework loop: 1) Thought (LLM analyzes goal). 2) Action (LLM selects tool & arguments). 3) Observation (System executes tool & returns result). Loop repeats until final answer is reached.
Purpose: Enables AI to perform complex multi-step tasks independently (e.g., search web, summarize, execute code, send email).
Example: An AI Agent given "Find product price on Amazon and email me the summary".
# ReAct Loop Cycle: # Goal ---> Thought: "I need data" ---> Action: [Search API] ---> Observation: Data received ---> Final Answer
Task: Trace a ReAct loop execution log for an agent tasked with booking a flight ticket.

14. Agent Memory & Conversation State Management

Meaning: Maintaining state and short-term/long-term memory across agent execution steps.
Definition: Uses **Buffer Memory** (full history), **Summary Memory** (LLM summarizes past turns), or **Vector Memory** (retrieving relevant past memories via semantic search). Preserved across sessions using databases (Redis, PostgreSQL).
Purpose: Prevents context window overflow and ensures multi-turn chatbots remember user context permanently.
Example: Summarizing a 50-turn customer service chat into 3 bullet points to save context space.
// Short-term Memory: Last N messages in context // Long-term Memory: Summarized state saved in Redis / Vector DB

15. Local LLM Execution (Ollama, LM Studio & Hugging Face)

Meaning: Running open-weight Large Language Models locally on developer machines or private servers without cloud API dependencies.
Definition: Tools like **Ollama** or **LM Studio** download and run quantized models (Llama 3, Mistral, Gemma, Phi-3) locally, exposing OpenAI-compatible local HTTP REST API endpoints (`http://localhost:11434`).
Purpose: Ensures 100% data privacy, zero API usage costs, and offline development capabilities.
Example: Running `ollama run llama3` in terminal and querying it locally via API.
# Terminal: ollama run llama3 # Fetching local Ollama endpoint in JS: const response = await fetch('http://localhost:11434/api/generate', { method: 'POST', body: JSON.stringify({ model: 'llama3', prompt: 'Hello local LLM!' }) });

16. AI Safety, Moderation APIs & Content Guardrails

Meaning: Enforcing strict safety policies to prevent prompt injection attacks, toxic content, and data leaks in production AI systems.
Definition: Uses **OpenAI Moderation API** or guardrail frameworks (NeMo Guardrails, Llama Guard) to inspect inputs/outputs for hate speech, self-harm, sexual content, and system prompt override attacks before processing.
Purpose: Protects enterprise reputation and guarantees compliance with AI safety standards.
Example: Checking user input against the free OpenAI Moderation API endpoint before passing to GPT-4.
const moderation = await openai.moderations.create({ input: userInput }); if (moderation.results[0].flagged) { throw new Error("Input violated AI safety guidelines."); }

17. Token Streaming (Server-Sent Events) & Cost Optimization

Meaning: Streaming LLM response tokens back to the user interface in real-time as they are generated.
Definition: Uses Server-Sent Events (SSE) and HTTP chunked transfer encoding (`stream: true`). Eliminates waiting 10 seconds for full completions by displaying text character-by-character as tokens arrive. Cost optimization uses cheaper models (e.g., `gpt-4o-mini`) and aggressive prompt caching.
Purpose: Delivers instantaneous perceived user responsiveness matching ChatGPT UI experience.
Example: Streaming completion tokens to terminal or response stream.
const stream = await openai.chat.completions.create({ model: 'gpt-4o-mini', messages: [{ role: 'user', content: 'Write a story' }], stream: true, }); for await (const chunk of stream) { process.stdout.write(chunk.choices[0]?.delta?.content || ''); }
