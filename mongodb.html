📅 Lecture 01 | Module 01: Intro to MongoDB, Differences & Core Architecture Day 1

1. Intro to MongoDB

Meaning: A popular, open-source NoSQL (non-relational) document-oriented database.
Definition: MongoDB stores data in flexible, JSON-like documents called BSON (Binary JSON), allowing data fields to vary from document to document without a fixed schema.
Purpose: Designed for high scalability, real-time analytics, rapid development, and handling unstructured or semi-structured data.
Example: Storing user profiles with variable attributes (e.g., some users have Twitter handles, others have phone numbers).
// MongoDB Document (BSON/JSON format) { "_id": ObjectId("65a1b2c3d4e5f67890a1b2c3"), "name": "Somesh Hadve", "skills": ["JavaScript", "React", "MongoDB"] }
Task: Explain in your notebook why BSON is used internally by MongoDB instead of plain text JSON.

2. SQL vs NoSQL Differences

Meaning: The structural and architectural differences between Relational (SQL) and Non-Relational (NoSQL) databases.
Definition: **SQL** databases (MySQL, PostgreSQL) use fixed table schemas, rows, columns, and foreign key JOINs. **NoSQL** databases (MongoDB) use dynamic schemas, JSON documents, collections, and horizontal scaling (Sharding).
Purpose: Helps developers choose the right database system based on schema stability and scaling requirements.
Example: SQL = Strict Banking Systems; NoSQL = Social Media feeds, IoT logs, and E-commerce catalogs.
# SQL: Rigid Tables & Rows | Vertical Scaling (Scale Up CPU/RAM) # NoSQL: Flexible Documents & Collections | Horizontal Scaling (Scale Out Nodes)
Task: Write a comparison table in your notebook highlighting 4 key differences between MySQL and MongoDB.

3. Rows & Columns vs Documents & Collections

Meaning: Mapping traditional SQL database concepts to MongoDB NoSQL terminology.
Definition: A SQL **Table** corresponds to a MongoDB **Collection**. A SQL **Row/Record** corresponds to a MongoDB **Document**. A SQL **Column** corresponds to a MongoDB **Field**.
Purpose: Enables developers transitioning from SQL to quickly grasp MongoDB organizational hierarchy.
Example: `users` table with 5 rows = `users` collection containing 5 BSON documents.
// SQL Term --------> MongoDB Term // Database --------> Database // Table -----------> Collection // Row -------------> Document // Column ----------> Field // Joins -----------> $lookup / Embedded Documents

📅 Lecture 02 | Module 02: CRUD Operations & Querying Deep Dive Day 2

4. CRUD: Create Operations (`insertOne`, `insertMany`)

Meaning: Inserting single or multiple BSON documents into a collection.
Definition: `db.collection.insertOne(doc)` inserts one document. `db.collection.insertMany([doc1, doc2])` inserts an array of documents. MongoDB automatically generates a unique `_id` field if not provided.
Purpose: Used for saving new records such as user registrations, product additions, or blog posts.
Example: Inserting a new product document into the `products` collection.
db.products.insertOne({ name: "Wireless Mouse", price: 499, category: "Electronics", inStock: true });
Task: Use `insertMany()` to add 3 student documents with fields `name`, `age`, and `grade` to the `students` collection.

5. CRUD: Read Operations & Query Operators (`find`, `$gt`, `$in`, `$or`)

Meaning: Querying documents from a collection with comparison and logical filter conditions.
Definition: `db.collection.find(query, projection)` fetches documents matching query filters. Comparison operators: `$gt` (greater than), `$gte`, `$lt`, `$lte`, `$ne`, `$in` (matches values in array). Logical: `$or`, `$and`, `$not`.
Purpose: Powers search filters, price ranges, and conditional data retrieval.
Example: Finding products priced over 500 OR in category 'Electronics'.
db.products.find({ $or: [ { price: { $gt: 500 } }, { category: { $in: ["Electronics", "Gadgets"] } } ] });
Task: Write a query that finds all students aged 18 or older with grade "A".

6. CRUD: Update Operations (`updateOne`, `updateMany`, `$set`, `$inc`)

Meaning: Modifying existing fields or adding new fields to stored documents.
Definition: `updateOne(filter, update)` modifies the first matching document. `updateMany(filter, update)` modifies all matching documents. Update operators: `$set` (overwrites/adds field), `$inc` (increments numeric field), `$push` (adds item to array).
Purpose: Allows updating user profile data, incrementing inventory stock counts, or appending array tags.
Example: Incrementing price by 50 and setting `onSale: true`.
db.products.updateMany( { category: "Electronics" }, { $inc: { price: 50 }, $set: { onSale: true } } );
Task: Write an `updateOne()` query that updates a student's age and adds a new `email` field.

7. CRUD: Delete Operations (`deleteOne`, `deleteMany`)

Meaning: Removing documents matching specific criteria from a collection.
Definition: `deleteOne(filter)` deletes the first matching document. `deleteMany(filter)` deletes all documents matching the filter. Passing an empty filter `{}` deletes ALL documents in the collection!
Purpose: Used for deleting user accounts, removing out-of-stock items, or purging temporary data.
Example: Deleting all out-of-stock products.
db.products.deleteMany({ inStock: false });
Task: Delete a single student document by `_id` using `deleteOne()`.

📅 Lecture 03 | Module 03: Indexing & Aggregation Framework Day 3

8. Indexing in MongoDB (`createIndex`)

Meaning: Data structures that improve query execution speed by avoiding full collection scans.
Definition: Created using `db.collection.createIndex({ field: 1 })` (1 for ascending, -1 for descending). Supports Single Field Indexes, Compound Indexes, and Unique Indexes.
Purpose: Crucial for query performance optimization on collections containing millions of documents.
Example: Creating a unique index on the `email` field.
db.users.createIndex({ email: 1 }, { unique: true }); db.products.createIndex({ category: 1, price: -1 });
Task: Create a compound index on `category` and `name` fields in your products collection.

9. Aggregation Framework (`$match`, `$group`, `$project`, `$sort`)

Meaning: A data processing pipeline that processes documents through multi-stage pipelines to transform and return aggregated results.
Definition: Executed via `db.collection.aggregate([stage1, stage2, ...])`. Key pipeline stages: **`$match`** (filters documents), **`$group`** (groups by key and computes `$sum`, `$avg`, `$min`, `$max`), **`$project`** (shapes output fields), **`$sort`** (orders results).
Purpose: Powers complex analytics, sales reporting, category totals, and data transformations.
Example: Calculating total sales and average price per category.
db.products.aggregate([ { $match: { inStock: true } }, { $group: { _id: "$category", totalProducts: { $sum: 1 }, avgPrice: { $avg: "$price" } } }, { $sort: { totalProducts: -1 } } ]);
Task: Write an aggregation pipeline that groups students by `grade` and calculates the average age for each grade.

📅 Lecture 04 | Module 04: Data Modeling & Backend Integration Day 4

10. Data Modeling (Embedded vs Referenced Documents)

Meaning: Designing MongoDB document schemas based on application access patterns.
Definition: **Embedded Documents (Denormalization)** store related sub-data directly inside a single document (ideal for 1-to-1 or 1-to-Few relationships). **Referenced Documents (Normalization)** store ObjectIds pointing to documents in another collection (ideal for 1-to-Many or Many-to-Many relationships).
Purpose: Optimizes read/write efficiency and prevents exceeding the 16MB document size limit.
Example: Embedding address inside user document vs referencing orders by ObjectId.
// Embedded Schema { name: "Alex", address: { street: "123 Main St", city: "Mumbai" } // Embedded } // Referenced Schema { name: "Alex", orders: [ ObjectId("65a1..."), ObjectId("65a2...") ] // Referenced }
Task: Explain when to use Embedded documents versus Referenced documents in your notebook.

11. MongoDB with Backend (NodeJS + Mongoose ODM)

Meaning: Connecting MongoDB to a NodeJS/Express backend using Mongoose Object Data Modeling (ODM).
Definition: Mongoose provides a straight-forward, schema-based solution to model application data (`new mongoose.Schema()`), enforce validation, and run async queries (`Product.find()`).
Purpose: Brings structure, schema validation, and middleware hooks to MongoDB within Node backend applications.
Example: Defining a Mongoose Schema and Model in NodeJS.
const mongoose = require('mongoose'); // Connect mongoose.connect('mongodb://127.0.0.1:27017/shop_db'); // Schema & Model const productSchema = new mongoose.Schema({ title: { type: String, required: true }, price: { type: Number, min: 0 } }); const Product = mongoose.model('Product', productSchema);

📅 Lecture 05 | Module 05: Backup, Restore & Cloud Deployment Day 5

12. Backup & Restore (`mongodump` & `mongorestore`)

Meaning: Database maintenance utilities used to export binary backups and restore them.
Definition: `mongodump --db=dbname --out=/backup/dir` exports collection data to BSON files. `mongorestore --db=dbname /backup/dir/dbname` restores the data back into MongoDB.
Purpose: Essential for disaster recovery, data migration, and routine server backup schedules.
Example: Backing up a local database before server maintenance.
# Export backup mongodump --db=school_db --out=./backup # Restore backup mongorestore --db=school_db ./backup/school_db
Task: Run `mongodump` in terminal to back up a database and inspect the generated BSON files.

13. MongoDB Cloud Deployment (MongoDB Atlas)

Meaning: Hosting MongoDB databases on fully managed cloud infrastructure via MongoDB Atlas.
Definition: Cloud-hosted DBaaS (Database-as-a-Service) providing automated scaling, cluster management, IP whitelisting, database user security, and connection strings (`mongodb+srv://...`).
Purpose: Deploys production-ready MongoDB databases accessible securely by live cloud backends (Render, Heroku, AWS).
Example: Connecting a NodeJS application to MongoDB Atlas using an environment URI string.
const ATLAS_URI = "mongodb+srv://admin:secret123@cluster0.abcde.mongodb.net/prod_db"; mongoose.connect(ATLAS_URI) .then(() => console.log('Connected to MongoDB Atlas Cloud!'));
